## 📄 Research Papers — Top Picks
- **MistyPilot: Enabling Social-Robot Control through Multi-Agent LLM Skill Orchestration** — Wang, Dong, Nwogu, Setlur, Govindaraju · https://arxiv.org/abs/2608.15549
  MistyPilot turns natural-language instructions into orchestrated skill calls on the Misty social robot using a Task Router that dispatches to two specialists: a Physically Interactive Agent for sensor-triggered control and a Social Interaction Agent for dialogue and task-state management. The social agent reuses prior generation results when applicable to cut latency. Evaluation covers five component suites on the physical robot plus a 12-participant study, with high accuracy on routing, sensor-skill binding, and skill extension up to 100 skills, and lower variance than a single-agent baseline. **Why it matters:** Concrete evidence that router-plus-specialist decomposition beats one monolithic agent as a skill library grows.

- **HarnessEval-W: Agentifying the Evaluation of Visual Worlds** — HF Papers (Chen, Sun, Gao et al.) · https://huggingface.co/papers/2608.16859
  HarnessEval-W replaces fixed-rubric world-model scoring with an agentic evaluation pipeline: it decomposes each evaluation question into measurable subproblems, spawns sub-agents with tailored diagnostic tools, and has a parent agent validate the evidence into a verdict. Every judgment becomes a transparent evidence tree rather than a bare scalar. Applied to 18 world models over 330 cases, its verdicts align closely with human preference while giving fine-grained diagnoses of each rollout. The pipeline is open-sourced as a live, community-extensible benchmark. **Why it matters:** Brings the LLM harness pattern to benchmarking itself — evaluations you can audit, not just numbers you must trust.

- **VibeWorlding: Can Multimodal Agents Construct 3D Open Worlds End-to-End?** — Ning, Ye, Wu et al. · https://arxiv.org/abs/2608.15265
  VibeWorlding benchmarks and trains multimodal agents that infer user intent, plan scene layout, invoke 3D tools, and reflect over multi-turn feedback. It ships VWE-BENCH (2,616 assets, 323 annotated seed worlds, 6,828 synthesized queries) and VibeWorlding-Gym, an RL post-training sandbox exposing asset retrieval, editing, and rendering as MCP tools with a rubric verifier for physical feasibility and intent fulfillment. Frontier MLLMs stay under 60% success, with precise 3D editing the bottleneck; RL-trained open models close and even pass that gap. **Why it matters:** MCP is becoming the standard tool interface for RL environments, not just for chat assistants.

- **When State Becomes an Attack Surface: State-Semantic Injection in LLM-Driven Embodied Agents** — Liu, Guo, Zhang et al. · https://arxiv.org/abs/2608.16806
  The paper studies embodied LLM agents that ground plans in scene state, object attributes, spatial relations, and execution feedback before handing actions to skill libraries and controllers. It argues that this state channel — not just prompts or retrieved documents — is itself an injectable attack surface. The analysis is set against the SayCan / Code as Policies / ProgPrompt / VoxPoser planning lineage and VLA models such as PaLM-E, RT-2, and GR00T N1. **Why it matters:** Prompt-injection defenses that only sanitize text miss the environment-state path into an embodied agent's planner.

- **Skill2Query: Exploiting Skill Structure to Generate Pseudo-Queries for Agent Skill Retrieval** — Ding, Guo, Lu et al. · https://arxiv.org/abs/2608.16071
  Skill2Query parses a skill document into a Skill Knowledge Graph, then generates pseudo-queries via style mimicking, template generation, and parameter filling — so queries are grounded in real capabilities and parameters rather than just topic. From roughly 30K skills it generates 700K pseudo-queries usable for index augmentation, query expansion, and retriever training. Across TheoremQA, LogicBench, ToolQA, and CHAMP it improves sparse, dense, and skill-routing retrieval by an average 6.70 pp Recall@1, and better retrieval translates into higher end-to-end agent success. **Why it matters:** Skill retrieval quality becomes the bottleneck once an agent's skill library outgrows the context window.

- **GenRouter: Unified Workflow Routing for Agentic Image Generation** — HF Papers (Chen, Hou, Shu et al.) · https://huggingface.co/papers/2608.16721
  GenRouter standardizes heterogeneous agentic image pipelines into GenCanvas — a common set of primitives and executable templates — then routes each prompt to the cheapest adequate workflow via demand profiling, experience matching, and Pareto filtering. This fixes compute-mismatch, where trivial prompts get pushed through heavyweight retrieval-and-reflection pipelines. Reported results: better visual alignment with over 95% lower execution cost and 65% lower latency than static heavy pipelines, plus self-evolution from accumulated experience. **Why it matters:** Adaptive workflow routing is the obvious cost lever for any agent stack with expensive optional steps.

- **Ventor-QTest: Threat-Model-Driven Verification of Vendor-Hosted LLM APIs** — Wu, Ying, Wu et al. · https://arxiv.org/abs/2608.16391
  Ventor-QTest is a black-box audit for third-party APIs serving open-weight models, requiring no logprobs from the target. A repeated-request component reconstructs an output distribution from text counts and reports average fidelity loss (AFL); a long-sequence component reports extreme fidelity loss (EFL) from run-level surprisal tails. AFL tracks a logprob-derived KL comparator closely, and while neither metric correlates with GPQA-Diamond accuracy, high EFL coincides with declining Terminal-Bench pass rates as task exposure grows. The implementation is open-sourced under Tencent's AI-Infra-Guard. **Why it matters:** If you buy inference from a reseller, short-answer benchmarks won't reveal the fidelity loss that kills long-horizon agent runs.

- **SkillCommit: Evolving Agent Skills through Behaviorally Validated Scope Expansion** — He, Yang · https://arxiv.org/abs/2608.15165
  SkillCommit builds a hierarchical skill library online, keeping each new experience as an instance-specific patch and only abstracting skills upward when cross-instance replay plus an LLM mechanism check confirm they share a real behavioral mechanism. A merge is committed only if it preserves every constituent skill's validated behavior — avoiding the failure mode where semantic similarity fuses incompatible strategies. Gains hold across RuleArena, OpenExempt, and KOR-Bench, and learned skills transfer across model scales and families. **Why it matters:** Behavioral validation, not embedding similarity, is what stops a self-improving skill library from regressing.

- **VCE-Skill: Enhancing Skill Self-Evolution with Version-Change Experience** — Chen, Ye, Wang et al. · https://arxiv.org/abs/2608.16544
  VCE-Skill mines public skill version histories as a source of evolution priors, distilling noisy implementation-specific diffs into structured version-change experience and fusing it with trajectory-derived proposals from a base evolver. A pilot study shows the two sources are complementary: version history gives reusable priors, trajectories give task-grounded evidence. Mean scores rise 3.20–4.98 points, with stronger cross-model transfer for the resulting skills. **Why it matters:** A skill repo's commit history is usable training signal for improving those same skills.

- **LatentSkill: From In-Context Textual Skills to In-Weight Latent Skills for LLM Agents** — Yu, Zhou, Xu et al. · https://arxiv.org/abs/2606.06087
  LatentSkill uses a pretrained hypernetwork to convert textual skill documents into plug-and-play LoRA adapters, moving skill knowledge from context space into weight space while keeping modular loading, scaling, and composition. This removes per-step skill tokens and stops shipping skill content as plaintext. On ALFWorld it gains 21.4 and 13.4 points on seen and unseen splits with 63.9% fewer prefill tokens; on Search-QA it gains 3.0 exact match with 71.8% fewer tokens per step. The generated LoRAs form a structured semantic geometry and compose through parameter-space arithmetic. **Why it matters:** A credible route past the context-budget ceiling that limits how many skills an agent can carry.

- **HyMem: Hierarchical Context Management for Long-Horizon Agents via Information Isolation** — Wang, Xiao, Cui et al. · https://arxiv.org/abs/2608.15703
  HyMem splits an agent's context into functional layers instead of compressing or retrieving over one flat context, keeping high-level planning separate from execution traces. An isolated reasoning module handles complex subtasks without polluting the persistent planning context, and a memory module carries task progress across context refreshes via structured summaries. With DeepSeek-V4 it reaches 66.7% and 61.3% average Pass@1 on GAIA and Browsecomp-plus, beating the strongest baseline by 6.1 and 4.7 pp. **Why it matters:** Isolating sub-agent reasoning from the main context is a cheap architectural fix for long-horizon context rot.

- **TDD-Agent: Test-Driven Reasoning for Code Generation** — Yu, Li, Li et al. · https://arxiv.org/abs/2608.16742
  TDD-Agent makes the model write executable tests before implementation, then iteratively refines code and tests together using execution feedback, rather than treating generated tests as static post-hoc validators. A prompt-only variant already beats reasoning-prompt baselines on LiveCodeBench, and the full agent outperforms retrieval- and agent-based baselines on repository-level RepoEval. Refinement improves the tests too — higher pass rates, coverage, and mutation scores. **Why it matters:** Empirical support for making test-first a structural part of coding-agent loops rather than a review afterthought.

- **Kozuchi Agent: A Language-Agnostic Open-Weight Agent for Software Repair** — Bahrami, Kimura, Munakata et al. · https://arxiv.org/abs/2608.15579
  Kozuchi is a repair agent with explicit phases, persistent state, deterministic tools, and a model-independent action interface, operated through a reusable CI evaluation pipeline. With locally hosted Qwen3.5-27B, no fine-tuning, and TTS@8, it resolves 374/500 SWE-bench Verified instances, ranks first among strict open-weight submissions on Multi-SWE-bench Java (41/128), and first among open-weight systems on Python. Per-phase behavior stays within ±5 pp across languages; remaining failures are semantic correctness and candidate selection, not edit formatting or proprietary model access. **Why it matters:** A 27B open-weight local model plus disciplined agent scaffolding gets within reach of proprietary repair agents.

- **OGX: An Open-Source, Vendor-Neutral Generative AI Application Server** — Arceo, Han, Farrellee et al. · https://arxiv.org/abs/2608.14580
  OGX implements the OpenAI, Anthropic, and Google API surfaces over pluggable backends so agentic apps can swap inference engine, vector store, and safety provider without code changes. Its focus is the Responses API for server-side agentic orchestration per the Open Responses spec, with 20+ inference providers, 13 vector store backends, and a companion Kubernetes operator. It already serves as a self-hosted backend for Claude Code, Codex CLI, OpenCode, and OpenHands, with 8,400+ GitHub stars and 242 contributors. **Why it matters:** A practical decoupling layer if you want to run coding agents against self-hosted models.

- **R³-Bench: LLMs Struggle with Resource-Rational Reasoning under Shared Budgets** — HF Papers (Wang, Ma, Liu et al.) · https://huggingface.co/papers/2608.16033
  R³-Bench evaluates six-problem suites under a shared compute budget across math, competitive programming, and abstract reasoning, in tool-free and agentic settings — unlike benchmarks that give each task its own budget. An offline oracle calibrated from matched single-problem response curves matches or beats the models' actual contest performance in all 72 cells and is strictly higher in 71. Even equal-allocation replay beats contest performance for four of six models under moderate pressure, and trajectory diagnostics show little strategy updating. **Why it matters:** Models can solve the problems but can't budget across them — a direct weakness for agents managing their own token spend.
