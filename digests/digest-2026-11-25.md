## 📄 Research Papers — Top Picks
- **CAPE: Coordinating Calibration and Search for Tool-Use Policies** — Wang et al. · https://arxiv.org/abs/2611.31938
  CAPE is a training-free compiler for tool-use policies where a call can fail due to hidden tool configuration (delimiters, dates, record layouts). It keeps an executable policy at all times, directs calibration to calls that can improve it, and certifies optimality when bounds meet. Evaluated on CSV and JSON workflows built from 64 requests. **Why it matters:** Treats tool-call reliability as a budgeted calibration problem rather than trial and error.
- **VISE: Verifier-Independent Skill Self-Evolution with Feedback from Tool Implementations** — Liu et al. · https://arxiv.org/abs/2611.32480
  VISE refines agent skills without task verifiers by reading tool source code to extract capabilities, inputs and output formats, then comparing them with the SKILL.md and execution trace to recommend specific edits. As an extra stage on four evolution methods it lifts task success by 9.14-13.35 points on SkillsBench and SkillLearnBench. **Why it matters:** Grounds skill revision in tool implementations, useful where no verifier exists.
- **SkillCore: Internalizing Generalizable Skills via Scaffolding-Removed Fine-Tuning** — Liu et al. · https://arxiv.org/abs/2611.32246
  SkillCore internalizes generalizable runtime skills (code review, debugging) into the model by stripping skill-loading scaffolding from real agent trajectories and fine-tuning on direct execution. A small share of skill-native trajectories keeps access to genuinely external skills. It improves task completion on a held-out skill-free evaluation. **Why it matters:** Moves common procedures from optional add-ons into model capability.
- **SpatialCraft: Evolving Procedural Intelligence from Experience and Skills for Spatial Reasoning Agents** — Liu et al. · https://arxiv.org/abs/2611.31475
  SpatialCraft lets a frozen tool-using spatial reasoning agent improve orchestration without parameter updates. It keeps Experiences (condition-action tactics from contrasting rollouts) and Skills (multi-step procedures with activation and termination conditions), with a Contrastive Utility Score estimating each Experience's effect. **Why it matters:** Concrete recipe for self-evolving tool orchestration in multimodal agents.
- **Leto: Utility-Centric Agent Memory** — Chen, Paracha · https://arxiv.org/abs/2611.33005
  Leto is a memory system for LLM agents that values memory by its utility for future responses, not fidelity to the past. It indexes conversation details and uses memory replay to anticipate and supply context beyond what the request states, then checks the utility of served context. **Why it matters:** Reframes agent memory as prediction, directly relevant to long-lived assistants.
- **ExpGuard: Guarding Long-Horizon LLM Agents against Corrupted Experience** — Chen et al. · https://arxiv.org/abs/2611.32085
  ExpGuard defends long-horizon agents that distill past trajectories into reusable experience against corrupted or adversarial guidance. It scores attack and failure risk on a provenance-aware heterogeneous graph before reuse, trains with counterfactual replays, and repairs risky experiences online. **Why it matters:** Experience reuse is an emerging attack surface for persistent agents.
- **Learning What vs. Learning How: Decomposing Task and Interface Competence in Agentic Training** — Lee et al. · https://arxiv.org/abs/2611.31427
  Separates task competence from interface competence in agentic training across four benchmarks. Multi-harness distillation only helps when training preserves competence on the inference-time interface; single-harness training can interfere with it. **Why it matters:** Explains why agents fail under a new harness despite knowing the task.
- **Fix How It Acts, Not How It Thinks: Surgical Fine-Tuning of Frontier LLMs** — Sandha et al. · https://arxiv.org/abs/2611.32064
  Merge-aware fine-tuning addresses LoRA fixes for agent missteps (repeating failed steps, declaring done too early) that vanish when merged into BF16 or FP8/NVFP4 checkpoints. Training on the rounded merged weights keeps the update from disappearing at export. **Why it matters:** Practical fix for small behavior patches lost to quantized releases.
- **SOARS: System One Assisted Reranking for Agentic Search** — Bigdeli et al. · https://arxiv.org/abs/2611.32917
  SOARS is a training-free System One reranker for deep search agents that picks relevant passages and reranks candidates in one call using the question and the sub-query. On BrowseComp-Plus it raises GPT-5.4 Mini accuracy from 73.9% to 84.7% while cutting search calls from 23 to 14. **Why it matters:** Cheaper, faster reranking inside agent search loops.
- **CoT-Proxy: Cross-Format Transfer for Distilling Long-Horizon Policies** — Kopiczko et al. · https://arxiv.org/abs/2611.33148
  CoT-Proxy distills long-horizon policies from a teacher's actions alone, with an empty reasoning block and a KL loss against the student's own generations. The policy transfers to inference with thinking on. Qwen3-4B on AppWorld rises from 7% to 18% and Qwen3-32B from 12% to 25%. **Why it matters:** Distilling from closed teachers without access to their chain-of-thought.
- **Next-Manip: On-Demand Agent-Policy Collaboration for Robotic Manipulation** — Liu et al. · https://arxiv.org/abs/2611.32533
  Next-Manip decouples executor allocation from costly agent inference in robotic manipulation. A lightweight Agent Invocation Controller decides when to call the multimodal agent versus the learned policy, and Task Dynamics Context packages in-context changes into compact task references. **Why it matters:** Cuts agent calls by routing between agent and policy on demand.
- **Boundary-Aware Policy Learning for Agent-Orchestrated Robot Manipulation** — Fang et al. · https://arxiv.org/abs/2611.32238
  Boundary-Aware Policy Learning shapes and expands the handoff boundary of a visuomotor policy so an orchestrating agent knows when it can safely invoke it. Boundary-Explicit Training fine-tunes on contact segments with diverse start poses, then Boundary-Expanding Self-Improvement retrains on successful rollouts. **Why it matters:** Addresses the agent-to-policy handoff, a common failure point in agent-orchestrated robots.
- **Coding4Games: Can Modern Coding Agents Play Modern Video Games?** — Coding4Games authors · https://huggingface.co/papers/2611.31974
  Coding4Games benchmarks whether coding agents can write standalone programs that play 15 modern video games from visual input, then freeze them and test without any language-model inference. Development and test are strictly separated. **Why it matters:** Tests coding agents on long-horizon, perception-heavy program synthesis.
- **MAGPIE: Agentic Multi-Reference Image Generation via Executable Scene Construction** — MAGPIE authors · https://huggingface.co/papers/2611.32462
  MAGPIE represents an intended image composition as a simplified 3D scene in an executable Blender program. A coding agent links each object to its reference, checks geometry and renders against the instruction, and revises the program; the render guides the image generator. It improves Qwen and FLUX on DreamOmni2 and SconeEval. **Why it matters:** Uses a coding agent as a verifiable planner for image generation.
