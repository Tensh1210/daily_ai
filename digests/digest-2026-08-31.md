## 📄 Research Papers — Top Picks

- **String: An Agentic OS Where Every App Is a Markdown File** — arXiv cs.AI · https://arxiv.org/abs/2608.28027
  String is an open-source runtime that treats agent-computer interaction as an OS problem: every app is a Markdown file. Instead of stuffing tool schemas into the agent's context on every turn, tool knowledge lives in a common layer that renders one view at a time as Markdown (SFMD format). The design targets the fact that an agent re-reads and re-pays for everything shown to it each turn. **Why it matters:** A concrete alternative to schema-heavy tool interfaces — directly relevant to anyone paying per-turn context cost for large MCP/tool catalogs.
- **ContextPilot: Teaching Agents for Proactive Context Management via Fine-grained RL** — arXiv cs.CL · https://arxiv.org/abs/2608.28476
  ContextPilot trains agents to manage their own working context with fine-grained RL. It argues existing proactive context-management methods are limited to search/delete/summarize with no global planning, long-term memory, or adaptive compression, and that uniform exploration over context actions is inefficient. The work expands the context-editing toolset and shapes RL credit assignment per action type. **Why it matters:** Long-horizon agents fail on context bloat; this makes context management a learned policy rather than a prompt heuristic.
- **ASA: Backbone-Training-Free Representation Engineering for Tool-Calling Agents** — arXiv cs.AI · https://arxiv.org/abs/2602.04935
  ASA (Activation Steering Adapter) adapts LLM agents to domain tool-calling without touching backbone weights. The authors identify a "Lazy Agent" failure mode: tool necessity is nearly perfectly decodable from mid-layer activations, yet the model stays conservative about entering tool mode — a representation-behavior gap. ASA steers activations at inference time instead of prompt/schema engineering or continual PEFT. **Why it matters:** Fixes under-calling of tools without retraining, avoiding the maintenance and forgetting costs of fine-tuning.
- **Agentao: A Policy-Governed Runtime Harness for Embeddable Tool-Using LLM Agents** — arXiv cs.AI · https://arxiv.org/abs/2608.13574
  Agentao is a local-first, policy-governed runtime for embeddable tool-using agents. It separates model-generated action proposals from host-authorized execution via a layered architecture: host-facing surfaces, a host contract, a runtime core, and a permission-mediated tool system. Threat targets include over-privileged actions, weak auditability, prompt injection, tool poisoning, and uncontrolled side effects. **Why it matters:** A reference architecture for the permission/approval layer every production agent harness eventually needs.
- **On the Maintenance and Co-evolution of Agent Plugins: An Empirical Study of Claude Code Plugin Marketplaces** — arXiv cs.AI · https://arxiv.org/abs/2608.28497
  An empirical study of Claude Code plugin marketplaces, asking whether agent plugins are maintained artifacts that co-evolve or one-off write-once files. Unlike traditional packages, agent plugins ship functionality as a mix of natural-language instruction files, scripts, and configs. The paper characterizes marketplace structure, maintenance activity, and co-evolution across those components. **Why it matters:** First empirical look at how the agent-skill/plugin ecosystem actually ages — useful signal for anyone maintaining skills.
- **Beyond Task-Only Matching: Personalized Skill Routing with Counterfactual Evaluation** — arXiv cs.AI · https://arxiv.org/abs/2608.28241
  Skill routing is framed as profile-conditioned retrieval rather than task-only semantic matching. The authors show that when users with incompatible constraints issue identical requests, a task-only router picks a semantically plausible but unsuitable skill. They add counterfactual evaluation to measure routing quality beyond surface relevance. **Why it matters:** As skill/tool libraries grow, routing correctness — not just retrieval similarity — becomes the bottleneck.
- **Set-shifting Behavioral Test for Harnessed Agents** — arXiv cs.CL · https://arxiv.org/abs/2607.13396
  A cognitive set-shifting test for harnessed agents: mount libraries of redundant tools where many tools solve the same task but differ in hidden reliability, then silently shift which tool group is reliable mid-session. A branching schedule with a stable control isolates the effect of each shift on agent behavior, across a panel of LLMs. **Why it matters:** Measures whether agents actually adapt when a tool silently degrades — a common real-world failure nobody benchmarks.
- **LLM-Based Agents for Software and Systems Security: Approaches, Applications, and Assessment** — arXiv cs.AI · https://arxiv.org/abs/2608.28490
  A systematization of LLM agents for software and systems security, covering how such agents are built, applied, and assessed. Security workflows are procedural — inspect artifacts, hypothesize, invoke tools, interpret, revise — which maps naturally onto agent loops. The survey notes the term "agent" is used inconsistently across this literature and works to pin down what has actually been demonstrated. **Why it matters:** Sets a baseline for how far autonomous security agents really are before teams delegate security decisions to them.
- **ReToolSQL: Agentic Reinforcement Learning for Robust Text-to-SQL** — arXiv cs.AI · https://arxiv.org/abs/2608.27796
  ReToolSQL is a two-stage text-to-SQL framework: supervised warm-start on rejection-sampled reasoning traces, then agentic RL fine-tuning over multi-turn tool-use trajectories. It targets the limitation that most RL-from-execution-feedback approaches treat SQL generation as single-turn, blocking iterative error recovery. The two stages act on complementary failure modes. **Why it matters:** Shows the SFT-then-agentic-RFT recipe generalizing to a concrete, high-value tool-use task.
- **Learning to Use Tools: Reinforcement Learning for Tool-Integrated Mathematical Reasoning** — arXiv cs.AI · https://arxiv.org/abs/2608.28447
  A controlled study of calculator tool-calling for math reasoning on the Countdown task. The authors first show calculation errors account for a substantial share of wrong answers, build SFT data teaching tool-use patterns and output interpretation, then apply on-policy RL (RLOO and variants) on top of the tool-formatted policy. **Why it matters:** Clean ablation of where tool use actually buys accuracy versus where the model was already fine.
- **WeAgent-MMSearch: Native Text-Vision Interaction for Multimodal Search Agents** — arXiv cs.AI · https://arxiv.org/abs/2608.28062
  WeAgent-MMSearch builds a multimodal agentic harness with native text-vision interaction, keeping tool-returned images in subsequent context instead of collapsing retrieval to text. It also addresses long-horizon failure compounding — tool-call errors, response-length overruns, timeouts, budget exhaustion — that otherwise discard salvageable trajectories and destabilize policy updates. **Why it matters:** Harness-level engineering, not just model tuning, is what makes multimodal search agents trainable.
- **PACE: Publisher-Adaptive Content Extraction via Agentic Automation** — arXiv cs.CL · https://arxiv.org/abs/2608.27466
  PACE is an agentic framework that learns publisher-specific web content extractors instead of relying on brittle general extractors or expensive per-page LLM extraction. It targets richer extraction goals — metadata, images, tables — where general-purpose tools break on publisher layouts. The agent automates the work normally done by hand-built parsers. **Why it matters:** Data-pipeline quality upstream of any RAG or training corpus; automates the most tedious part of web ingestion.
- **CEDAR: Automata as Verifiable Interfaces for Language-Guided Embodied Action** — arXiv cs.CL · https://arxiv.org/abs/2608.27797
  CEDAR grounds natural-language instructions for embodied agents as regular languages over environment event traces, using a counterexample-guided loop. An LLM makes semantic judgments while execution traces drive correction, and both skills and specifications are represented as deterministic finite automata. This gives a stable, composable, verifiable object where free-form generated code gives none. **Why it matters:** Turns constraint compliance into something checkable rather than eyeballed.
- **PCFBench: A Diagnostic Benchmark for Product Carbon Footprint Estimation** — arXiv cs.AI · https://arxiv.org/abs/2608.27716
  PCFBench is a diagnostic benchmark for product carbon footprint estimation that decomposes the workflow into independently-evaluable tasks requiring decomposition, retrieval, and ontology grounding. Existing evaluations either score only total emissions — hiding and cancelling errors — or score subtasks in isolation, missing compositional interactions. **Why it matters:** Good template for benchmarking any high-stakes agent workflow where the final number can be right for the wrong reasons.
- **See, Hypothesize, Validate: Multimodal Agentic Framework for Discovering Governing PDEs** — arXiv cs.AI · https://arxiv.org/abs/2608.27869
  MAGE organizes discovery of governing PDEs as a confidence-governed hypothesis-validation loop with four role-specialized multimodal agents, mirroring observation, hypothesis, and falsification. It aims past the limits of sparse/symbolic regression (predefined libraries, noise sensitivity) and naive LLM approaches (hallucination, no iterative refinement). **Why it matters:** Concrete example of agentic scientific discovery where the validation loop, not the model, does the heavy lifting.
