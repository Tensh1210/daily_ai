## 📄 Research Papers — Top Picks
- **SP-Mind: An Autonomous Reasoning Agent for Spatial Proteomics Analysis** — Yuan, Ji, Li, Li (arXiv cs.AI) · https://arxiv.org/abs/2606.24235
  SP-Mind is presented as the first autonomous agent unifying the spatial-proteomics pipeline from raw multiplexed tissue imaging through phenotype discovery. It is equipped with expert-curated biological analysis skills plus specialized computational tools, and converts natural-language queries into end-to-end workflows without manual orchestration. The target problem is fragmented workflows that currently need expert hand-wiring of heterogeneous tools. **Why it matters:** A concrete demonstration that curated skill libraries plus tool-calling can replace expert manual orchestration in a real scientific pipeline.

- **SkillZip: Contract-Preserving Graph Compression for Scalable Agent Skill Libraries** — Tan, Wang, Liu, Xu et al. (arXiv cs.CL) · https://arxiv.org/abs/2608.05604
  As agent skill libraries grow, the core problem is exposing the smallest sufficient executable context under a fixed context budget. SkillZip argues existing systems fail because of a unit mismatch — skills are retrieved as packages, compressed as text, then only converted to execution graphs after retrieval. It proposes a contract-bearing procedural unit so compressed routines stay executable, expandable, and updatable as skills evolve. **Why it matters:** Directly addresses the context-budget wall that hits every production agent once its skill library grows past a few dozen entries.

- **SkillCorpus: Consolidating and Evaluating the Open Skill Ecosystem for Real-World LLM Agents** — Wang, Yao, Sun, Hu et al. (arXiv cs.CL) · https://arxiv.org/abs/2607.15557
  SkillCorpus aggregates, curates, matches, and evaluates the public SKILL-file ecosystem at scale, filtering roughly 821,000 crawled skills into 96,401 organized by a 16-class taxonomy and three quality tiers. It then measures what that consolidated corpus is actually worth on real-world agent tasks. Motivation is that public skill repos are fragmented, redundant, and uneven in quality. **Why it matters:** First serious empirical bound on how much value the open agent-skill ecosystem actually delivers versus its headline volume.

- **EnvACE: Internalizing Environment Dynamics via World Rehearsal for Agentic Reinforcement Learning** — Xu, Yao, Chen, Guo et al. (HF Papers) · https://huggingface.co/papers/2608.06197
  EnvACE replaces external environment interaction during agentic RL training with "world rehearsal": the policy emits a tool call, then plays the environment to produce the induced response, and conditions later decisions on that rehearsed response. Both roles are optimized jointly end-to-end with task-success rewards. This avoids the cost of building and verifying executable environments or grounding external simulators. **Why it matters:** Removes the executable-environment bottleneck that makes long-horizon tool-use training expensive to scale.

- **When Self-Evolution Backfires: Pre-Commit Gating against Skill Contamination in LLM Agents** — Shang, Xu, Sun, Xia et al. (arXiv cs.CL) · https://arxiv.org/abs/2608.05810
  Self-evolving agents that distill skills from their own trajectories show a phase transition: past a critical pool size, new skills degrade rather than improve performance. The cause is structural — a defective skill becomes reference material for distilling later skills, forming cross-round contamination chains. The paper shows contamination is effectively irreversible, since removing the source skill does not erase the flawed reasoning descendants inherited, and proposes gating skills before commit. **Why it matters:** Post-hoc cleanup of a self-evolving skill library does not work, so admission control has to happen at write time.

- **SkillTrace: Multi-Trace Provenance Auditing for LLM-Agent Skill Reuse** — Chen, Wang, Jiang, Ma et al. (arXiv cs.AI) · https://arxiv.org/abs/2608.05204
  Skills are mixed-modality packages of metadata, instructions, code, tools, references, and workflows, so auditing their reuse is not the same problem as code-clone detection. SkillTrace extracts three provenance traces — Expression, Implementation, and operational structure — instead of relying on single-modality or whole-package similarity. This catches reuse that preserves only one facet of a skill. **Why it matters:** As skills become marketplace artifacts, provenance and license auditing need tooling that existing clone detectors cannot provide.

- **Search2Skill: Skill Distillation Beyond Knowledge Boundaries via Rubric-Based Reinforcement Learning** — Ye, Lan, Jiang, Ye et al. (arXiv cs.AI) · https://arxiv.org/abs/2608.05245
  Existing self-evolving skill methods build skills from the model's own parametric knowledge or trajectories, so they are bounded by what the model already knows. Search2Skill instead identifies the agent's capability gaps, searches external sources to fill them, and distills retrieved evidence into structured skills using rubric-based RL. The target is professional domain conventions and standard procedures that cannot be elicited from the agent alone. **Why it matters:** Breaks the self-distillation ceiling by grounding new skills in external sources rather than the model's priors.

- **SkillHEX: Improving Agent Skills via Hypothesis-Driven Autonomous Exploration and Exploitation** — Feng, Chen, Zhao, Zhang et al. (arXiv cs.AI) · https://arxiv.org/abs/2608.05628
  Test-time skill evolution faces sparse rewards where a single failure signal conflates multiple latent causes, and greedy single-incumbent refinement falls into an exploitation trap after an early misdiagnosis. SkillHEX is a closed-loop framework that couples hypothesis-driven exploration with exploitation under limited interaction budgets and no training or validation set. **Why it matters:** Practical recipe for on-demand skill repair in deployment, where you get few trials and no labeled validation data.

- **Comparative Approaches to Agent Retrieval over Large Skill Libraries** — Kolluru, Sportsman (arXiv cs.AI) · https://arxiv.org/abs/2608.06196
  Over a corpus of 690 skills, the authors compare a hybrid lexical + dense-embedding ranker for sparse on-demand loading against a typed knowledge graph encoding prerequisites, data flow, and ordering. On 117 realistic non-echoing queries the hybrid ranker hits the correct skill in the top five 73.5% ± 8.0 of the time, leaving about a quarter of queries unserved. Substituting graph neighbours for extra ranked results is evaluated as the intended design. **Why it matters:** Quantifies how much retrieval alone leaves on the table, and where graph structure has to take over.

- **To Call or Not to Call: A Framework to Assess and Optimize LLM Tool Calling** — Wu, Das, Amani, Nag et al. (arXiv cs.AI) · https://arxiv.org/abs/2605.00737
  Tool use is not uniformly beneficial — redundant or low-utility calls can hurt task performance as well as cost. The paper builds a decision-theoretic framework around three factors (necessity, utility, affordability) and analyses tool decisions through both a normative lens (true need/utility) and a descriptive lens (the model's self-perceived need/utility). The gap between the two is the actionable signal. **Why it matters:** Gives a principled cost model for the single most expensive decision an agent makes per step.

- **Screenshots or Tools? Eliciting Tool Use and Managing Multimodal Context in Hybrid GUI-MCP Computer-Use Agents** — Fan, Li, Ma, Tan et al. (arXiv cs.AI) · https://arxiv.org/abs/2608.03327
  On one identical GUI-MCP harness over OSWorld-MCP's 309 tasks, the same MCP tools improve a reasoning model by +4.0pp and degrade a non-reasoning model by −5.9pp. The difference is tool-decision behavior: the non-reasoning policy ignores, misnames, or falsely terminates around tools, while the reasoning model avoids those failures but still calls a tool on only 55/309 tasks — 23.9% of tool-reachable ones. The authors name this shortfall the adoption gap. **Why it matters:** Adding MCP tools can make an agent worse, and even good models under-adopt them by a factor of four.

- **SkillMOO: Multi-Objective Optimization of Agent Skills for Software Engineering** — Gong, Gu, Fei, Cao et al. (arXiv cs.SE/cs.AI) · https://arxiv.org/abs/2604.09297
  Coding-agent skills are usually static hand-crafted assets or evolved on pass rate alone, which ignores that a skill can lift success while sharply raising token cost or injecting misleading guidance. SkillMOO evolves skill bundles via LLM-proposed edits under NSGA-II Pareto selection on both pass rate and inference cost. Across all 16 SkillsBench SE tasks it ranks top on pass rate for 11 of 12 non-zero-pass tasks while cutting cost up to 31.7% versus static bundles. **Why it matters:** Treats prompt/skill engineering as a measurable multi-objective search instead of craft, with cost as a first-class objective.

- **StepReflect: Structured UI Transition Reflection for Mobile GUI Agents** — Guo, Liu, Gu, Wang et al. (arXiv cs.AI) · https://arxiv.org/abs/2608.05587
  Instead of open-ended multimodal reasoning after every action, StepReflect casts per-step GUI reflection as supervised structured prediction conditioned on explicit transition specs plus paired visual evidence. Training combines supervised fine-tuning, teacher-student distillation, and preference/reward refinement. The resulting 8B model reaches 82.16% transition-level accuracy on AndroidWorld, beating zero-shot GPT‑5.2 by 11.83 points. **Why it matters:** A small specialized reflector beats a frontier model on verification, which is the cheap half of a long-horizon agent loop.

- **HarnessOpt-Bench: Evaluating LLMs at Harness Optimization** — Ursekar, Shanker, Maurya, Yasser et al. (HF Papers) · https://huggingface.co/papers/2608.06301
  Agentic system capability depends on the harness — prompts, tools, control flow, memory, orchestration code — not just weights, making automated harness optimization both a lever and a capability test. HarnessOpt-Bench evaluates end-to-end harness optimization under expensive, stochastic evaluation, giving an optimizer LLM a seed harness plus graded feedback and a fixed budget. **Why it matters:** Establishes a shared protocol for measuring self-improvement of agent scaffolding, which so far has been reported anecdotally.

- **Trace Only What You Need: Structure-Aware On-Demand Hypergraph Memory for Long-Document QA** — Zai, Tan, Chen, Wang, Zhang (arXiv cs.CL) · https://arxiv.org/abs/2606.10921
  Structured RAG for long-document QA suffers from costly query-agnostic knowledge organization, underuse of original document structure, and no reuse of past reasoning. DocTrace is a multi-agent RAG framework with query-triggered knowledge organization, document-structure-aware retrieval, and experience-guided reasoning over a hypergraph memory. It targets answers depending on event order, section context, and cross-part evidence links. **Why it matters:** Building the index on demand per query avoids the dominant cost of graph-RAG pipelines.
