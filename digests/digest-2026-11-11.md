## 📄 Research Papers — Top Picks
- **Firefly: Illuminating Large-Scale Verified Tool-Call Data Generation from Real APIs** — Yuxuan Lu, Ziyi Wang et al. · https://arxiv.org/abs/2605.17558
  FireFly generates verified tool-call training data from real MCP servers. A strong LLM first explores the APIs along graph-guided DAGs, then tasks are written backward from the observed outcomes, so labels are correct by construction. A retrieval-augmented simulator caches the exploration results for offline, reproducible RL. The pipeline yields 5,144 verified tasks across 240 servers and 993 tools; a 4B model trained with GRPO matches Claude Sonnet 4.6 on the held-out test set and improves on Tau2-Bench, MCPMark, and MCP-Atlas. **Why it matters:** A practical recipe for training small but strong MCP tool-callers on real APIs.
- **Agent Architecture Cost-Success Trade-offs: A Controlled Evaluation across Enterprise-Style SOPs** — Subhrangshu Nandi, Hitesh Arora et al. · https://arxiv.org/abs/2611.12953
  The authors hold model, tasks, and tools fixed and compare four designs across 13 enterprise SOPs: a single function-calling agent, a skill-augmented agent, centralized multi-agent orchestration, and a triage swarm. No architecture wins across the board. The coordinated designs use 1.4–4.7× the tokens and 2.6–5.8× the latency for gains that are usually small and rarely significant, though high-quality skills do raise success. **Why it matters:** Strong evidence that a single agent should be the default before reaching for multi-agent setups.
- **Teaching the Harness: Student-Aware Skill Transfer for LLM Agents** — Chang Liu, Bo Wu · https://arxiv.org/abs/2611.13144
  In Student-Aware Teaching (SAT), a stronger teacher model builds a profile of a weaker agent, tests guesses about its weaknesses with diagnostic probes, and writes reusable skills. A skill is kept only if it raises success on development tasks. With Claude Sonnet 5 teaching DeepSeek-V4-Flash, success reaches 86.46%, against 81.04% for a teacher without the profile and 75.00% for the untaught student. Each student does best with its own skill library, and saved libraries keep their gains after the teacher is gone. **Why it matters:** Skills work best when written for the specific model and harness that will use them.
- **Program-Aided Patchable Skill Evolution** — Jiahao Wang, Yuqi Xiong et al. · https://arxiv.org/abs/2611.14019
  PASE pairs agent skills with executable programs instead of keeping them as pure natural-language documents. Because the procedural logic lives in editable code, it can be patched directly without rewriting the skill text. PASE beats all baselines by more than 2.8%, with more stable evolution and better generalization. **Why it matters:** Suggests skill files should ship scripts for procedures, not just prose.
- **Dynamic Mixed-Precision Routing for Efficient Multi-step LLM Interaction** — Yuanzhe Li, Jianing Deng et al. · https://arxiv.org/abs/2602.02711
  Only about 1% of agent steps are "critical", meaning low precision at that step turns a success into a failure. DMR trains a lightweight router on the model's hidden state to choose, step by step, between high- and low-precision versions of the same LLM, sharing one KV cache. Switching costs under 1 ms per step. **Why it matters:** Lowers agent inference cost without the success drop of fixed low-bit quantization.
- **ReTrace: Distilling Tool-Using Agents into Planner-Free Workflows** — Kaiyuan Hou, Yang Ping Kuo et al. · https://arxiv.org/abs/2611.14492
  ReTrace reads the explanations an agent writes with each tool call in logged runs, extracts the condition behind each step, and merges them into a rule document. From that document it generates a workflow in which code, not an LLM, picks the next step. On 79 production procedures it reaches 93.8% completion (agent: 96.8%) at 24% lower cost; on τ²-Bench it runs in 1.3 s instead of 170 s. **Why it matters:** A way to turn repetitive agent SOPs into cheap, deterministic workflows.
- **Which Successes Make Good References? Action-Sequence Alignment for Multi-Turn On-Policy Distillation** — Mufei Li, Nikki Lijing Kuang et al. · https://arxiv.org/abs/2611.13135
  In on-policy distillation for tool-use agents, the teacher can be given a successful trajectory as a reference, but a mismatched reference gives misleading supervision. The authors choose each reference by aligning action sequences with longest common subsequence (LCS), framed as an optimal transport problem. LCS is the only selector tested that beats reference-free distillation on ALFWorld and on all three τ³-bench airline metrics, and the gains carry over to the retail domain. **Why it matters:** A simple, cheap fix for better multi-turn agent distillation.
- **SteerDistill: Quantizing LLM Agents via Closed-Loop Teacher Steering** — Genming Cui, Xiangyu Li et al. · https://arxiv.org/abs/2611.13410
  A full-precision teacher guides a quantized student to revise its failed responses and refines that guidance based on how the student's actions play out. The student is then trained to make those corrections without guidance. Under W4A16 it beats the strongest quantized baseline by 1.67–2.18 points and stays within one point of BF16; on τ²-Bench it beats QeRL while using 67% fewer GPU hours. **Why it matters:** Makes 4-bit agents nearly as reliable as full-precision ones.
- **When Should Agents Remember? Falsification-Gated Self-Evolution for LLM Agents** — Runxuan Tang, Haoyu Gao et al. · https://arxiv.org/abs/2611.14326
  FGSE treats each lesson an agent wants to save as a hypothesis with a precondition, a behavior change, an expected effect, and a verifier. The lesson is tried in a temporary state and checked with transfer, falsification, and regression probes before it is committed. It reports 39.8 on WebArena and 78.8 on AppWorld, and only 3.6% of committed updates are harmful. **Why it matters:** A principled guard against agents filling their memory with bad lessons.
- **With Tools or Because of Tools? Tracing Capability Gains in Multimodal Agents** — Jiawei Guo, Donglei Yu et al. · https://arxiv.org/abs/2606.02357
  The authors compare two "thinking with images" agents (Thyme, DeepEyesV2) with tool-free and text-only versions. Tool access gives little consistent improvement, and 93–96% of the problems solved with tools are also solved without them. **Why it matters:** Agents may learn tool-calling patterns rather than gaining real ability from tools, so evaluations should measure the two separately.
- **MMDM: Measuring Massive Multitask Decision Making** — Junhao Shen, Qing Zong et al. · https://huggingface.co/papers/2611.14309
  MMDM is a benchmark of 5,448 questions in 16 categories for "System-1" models that make a decision in a single forward pass. It covers agent state tracking, tool and skill selection, preference judgments, and rubric scoring, with up to 1,024 options and inputs up to 64K tokens. Across 28 models, performance drops on interdependent options, constrained decisions, and multi-select tasks. **Why it matters:** Tests the routing and selection decisions that sit inside agent harnesses.
- **BioMem: Agentic Memory for Biomedical LLM Agents** — Mingchen Li, Yongkang Xiao et al. · https://arxiv.org/abs/2611.13426
  A systematic study of five agentic memory approaches with four LLMs, covering biomedical reasoning, clinical prediction, and long-term conversation. The authors propose HMRU, a training-free method that combines better retrieval with better use of the retrieved evidence, for an average relative gain of about 8.6%. **Why it matters:** Shows that keeping facts accurate in memory, not just retrieving them, is the bottleneck in high-stakes domains.
- **TreeAgent: Structure-Aware Memory Agent for Processing Long Hierarchical Data** — Wei Gu, Weiwei Qi et al. · https://arxiv.org/abs/2611.13946
  Instead of cutting long inputs such as API responses or HTML into flat token chunks, TreeAgent splits them into complete subtrees and tags each chunk with its structural path. This keeps the fields of a record together and preserves the hierarchy across memory updates, with theoretical bounds on the number of chunks. **Why it matters:** Better handling of large structured tool outputs that overflow the context window.
- **Mobile AI Factory: Building Specialized Language Models for Your Mobile Device** — Evan Li, Krishna Deshpande et al. · https://arxiv.org/abs/2611.13509
  Given a task and a target phone, an orchestrator LLM builds a fine-tuned, quantized small model. It decides whether to tune hyperparameters, mine real data, or generate synthetic examples, rolls back changes that hurt accuracy, and uses real measurements from the phone. The resulting on-device models beat five-shot frontier models on 5 of 10 tasks, and the search uses 19× less GPU time than training every variant. **Why it matters:** Agent-driven automated model building for phones, where real hardware measurements change the best choice.
- **MNN-Pocket-0.3B Technical Report** — MNN Team · https://arxiv.org/abs/2611.12311
  A 300M-parameter dense model with 32K context that takes 173 MB at INT4 and decodes up to 466 tokens/s on an iPad Pro M5. It was pre-trained on about 4.1T Chinese and English tokens, then post-trained with instruction fine-tuning, multi-teacher on-policy distillation, and quantization-aware training. **Why it matters:** Strong tiny models make on-device assistants on phones and smart glasses practical.
