## 📄 Research Papers — Top Picks
- **Graph-of-Skills: Dependency-Aware Structural Retrieval for Massive Agent Skills** — Liu, Li, Du, Wu, Gui, Kuang, Sun · https://arxiv.org/abs/2604.05333
  Skill libraries for LLM agents now reach thousands of entries: loading everything saturates the context window, while semantic retrieval misses upstream/downstream prerequisite skills so the retrieved bundle cannot execute. Graph-of-Skills (GoS) builds an executable skill graph offline and, at inference, retrieves a bounded dependency-aware bundle via hybrid semantic-lexical seeding, reverse-aware Personalized PageRank, and context-budgeted hydration. Across SkillsBench and ALFWorld with Claude Sonnet 4.5, MiniMax M2.7, and GPT-5.2 Codex it wins every model-benchmark block; on SkillsBench with GPT-5.2 Codex it lifts reward 7.0 points over full loading while cutting tokens 56.7%. Ablations show the gain comes from traversing dependencies backwards — replacing reverse traversal with forward propagation loses more than removing the graph entirely. **Why it matters:** Prerequisite-aware retrieval, not just semantic similarity, is what makes large skill libraries executable at a fraction of the token cost.

- **Harness or Model? Isolating the Harness Effect in Agentic Coding with a Contamination-Controlled Private Suite** — Arjmandi · https://arxiv.org/abs/2609.11987
  Tests the assumption that vendor-native harnesses solve more tasks than neutral ones, using paired same-model runs on a private, contamination-controlled suite of 256 repository and post-cutoff contest tasks. claude-agent-sdk vs deepagents on Opus 4.8 and openai-codex SDK vs deepagents on GPT-5.5 show no average advantage for either harness (-1.25 pp and +1.25 pp, CIs spanning zero). The Opus result hides opposite strata: the native harness trails by 9.0 pp on repository tasks but leads by 23.7 pp on contest tasks. The neutral harness cost 1.3–1.6x more per solved task on Opus 4.8, though missing usage records leave the billed ordering unresolved. **Why it matters:** Harness choice is not a free win on average — it shifts which task types you win and what you pay, so pick it per workload, not by vendor loyalty.

- **Skill Issue: Lessons from Optimizing Repository SKILLs for Coding Agents** — Kozyrev, Kozyrev, Podkopaev · https://arxiv.org/abs/2609.12742
  Coding agents read repository knowledge from SKILL.md files, and recent work synthesizes them by optimizing against a benchmark — but bare repos have no benchmark, and prior synthetic tasks are so easy a capable agent saturates them with no document. The authors mine harder tasks from merged pull requests reverted at a frozen base commit and score a document by whether the same agent does better with it than without. On three Kotlin repositories GEPA-found documents raise this score 4.9 pp on average, while SkillOpt leaves it at +0.1 pp; the GEPA gain cannot be separated from run-to-run variance at single-repo dataset sizes. A maintainer nonetheless found genuine project-insider knowledge in the generated documents. **Why it matters:** Auto-generated SKILL.md files may read well but proving they help requires harder, repo-derived tasks than one repository's history can supply.

- **Right Family, Wrong Skill: Evaluating Risk Exposure in Agent Skill Retrieval** — Ding, Ji, Liu, Duan · https://arxiv.org/abs/2606.10388
  Retrieved skills carry scripts, resource bindings, and execution assumptions, so a retriever can find the right capability family yet surface a risky sibling that differs on a controlling contract (resource, precondition, procedure, artifact). SameCapRisk-Bench pairs 1,190 helpful skills with query-specific risky siblings over 1,686 query cases, including 496 role-flip units where the two skills swap roles across paired queries. Public SkillRouter, SkillRet, and R3-Skill hit Recall@3 of 0.85–0.89 but expose the risky sibling at HSR@3 of 0.35–0.37; a score-and-cluster pipeline drops HSR@3 to 0.13–0.18, and a benchmark-trained resolver reaches HSR@3 0.007 at Recall@3 0.833. **Why it matters:** Skill routers should report harmful-sibling rate alongside recall, because same-family near-misses are the ones that execute wrong contracts silently.

- **Tasks over Application Manuals: Revealing Gaps in Long-Horizon Procedural Reasoning for Language Models** — Soni, Murtaza, Nie, Chandrasekhar, Wen · https://arxiv.org/abs/2609.13005
  TAM benchmarks whether LLMs can follow authoritative manuals with tens of thousands of interdependent rules to an exact answer, using human-validated tasks from ICD-10-CM clinical coding and U.S. federal sentencing offense-level computation. RAG, ReAct-style prompting, and an agent-harness baseline on GPT-5 reach at best 1% exact match on ICD-10-CM and 15.5% on sentencing. The authors argue short-horizon multi-hop benchmarks overestimate reasoning ability by skipping long rule-following procedures. Data and code are public. **Why it matters:** Following a long rulebook end-to-end is still nearly unsolved for frontier agents, which bounds what compliance-style automation can be trusted with today.

- **Retrieval-Augmented Generation for Scientific Code Understanding** — Nobile, Adelmann, Sadr · https://arxiv.org/abs/2609.12190
  Asks whether a fully local coding agent built on small open models can be useful by moving cost to an offline ingestion stage — parsing, structural graph construction, LLM-generated entity explanations, and embedding — followed by a lightweight online answering stage. On a 100-question benchmark over the IPPL C++ scientific codebase, judged by an independent frontier model, a 9B model scores highest (0.795) across seven answering models, beating larger models in the same pipeline and the same models inside Claude Code's retrieval architecture. Model family and retrieval quality matter more than parameter count. **Why it matters:** A codebase-specialised vector store lets small private models answer repository questions competitively, a practical path for in-house code that cannot leave the network.

- **SimSkill: A Self-Evolving LLM Agent for Skill and Knowledge Accumulation in Traffic Simulation** — Liu, Wang, Li, Bie, Ma · https://arxiv.org/abs/2609.03753
  SimSkill is a self-evolving agent around the SUMO traffic simulator that identifies capability gaps, generates and solves environment-grounded tasks, verifies solutions in an action–critic loop, and consolidates experience into episodic, procedural, and semantic memory. It autonomously builds a reusable skill library across the traffic-simulation workflow, improving verified success by up to 25 points on two held-out benchmarks across three backbones, with procedural and semantic memory contributing complementarily. Gains are backbone- and budget-dependent: memory does not help every model or uniformly cut inference cost. Control logic and knowledge live in natural language while an LLM binds them to executable tools. **Why it matters:** A worked example of natural-language-centred agent design where the agent grows its own skill library, with honest caveats about when memory does not pay off.

- **Mr.LHDR: A Benchmark for Multimodal Real-World Long-Horizon Deep Research Agents** — Guo, Cao, Zhao, Ning, Wang et al. · https://arxiv.org/abs/2609.11318
  Mr.LHDR evaluates deep research agents on long, irreducible chains of interdependent evidence: each question derives from a hidden node-relation graph requiring on average 12.1 intermediate conclusions at dependency depth 10.4, with at least one non-text element (image, map, PDF, chart, video frame) that changes the reasoning state. It scores final answers and intermediate conclusions via Overall/Strict Accuracy and dependency-aware checklist metrics. The strongest system reaches only 43.1% OA and 34.3% SA; removing images cuts the dependency-aware score 12.6 points, and strict accuracy falls as chains lengthen. **Why it matters:** Final-answer accuracy overstates research success; sustained dependency-consistent evidence integration is the actual bottleneck for deep research agents.

- **LifeMem: Enabling Lifelong Experience Reuse for LLM Agents** — Qiu, Li, Su, Liu, Che, Huang, Wang, Guo · https://arxiv.org/abs/2609.12655
  LifeMem targets two weaknesses of memory-based agents — poor transfer across environments and catastrophic forgetting as experience accumulates. During learning it clusters interaction trajectories by underlying workflow to extract reusable skills; at inference it recalls relevant skills and trajectories to guide actions. Experiments span 10 environments and 13k+ tasks with 2k newly annotated trajectories, showing reduced forgetting and better cross-task transfer. Analysis finds task-streaming order affects learning and that consolidating structurally similar trajectories boosts performance. **Why it matters:** Workflow-level clustering is a concrete recipe for turning raw trajectories into transferable skills without retraining the model.

- **GitSkills: A Dataset of Agent Skills on GitHub** — Destefanis, Graziotin, Vaccargiu, Ortu · https://arxiv.org/abs/2608.10906
  GitSkills is a dataset of 3,797,117 SKILL.md files collected from 282,200 public repositories in July 2026, nine months after Anthropic opened the skill format. Every occurrence is kept with repository, path, and content hash; identical files are grouped into 1,877,981 distinct contents, with one representative per group enriched with full text, parsed front matter, folder contents, repository metadata, and (for a subset) commit history. Skills are unusual artifacts: natural-language, selected probabilistically at runtime, with no registry, package manager, or type checker. Delivered as a single SQLite file. **Why it matters:** First population-scale corpus for studying how skills are written, copied, maintained, and abused — a prerequisite for skill-supply-chain security research.

- **K-Bench: A Benchmark for LLM Unlearning in Agentic Deployments** — Yu, Jiang, Wang, Ma, Wang · https://arxiv.org/abs/2609.12808
  Unlearning benchmarks like TOFU and MUSE certify forgetting from the final answer alone, counting refusals as forgotten. K-Bench shows this does not transfer to agents: it inspects all six channels a ReAct agent exposes (CoT, tool calls, tool observations, elicited summary, etc.) and counts a leak if the secret appears anywhere, placing the secret in the weights, the prompt, or the retrieval store. When the secret lives in the prompt or retrieval store, TOFU/MUSE report no leakage while the deployed agent leaks it on 22–86% of queries. When in the weights, none of twenty published methods demonstrably removes it; only an input-corruption intervention achieves selective forgetting. **Why it matters:** Answer-level unlearning certificates are meaningless once the model runs as an agent with tools — leakage moves to the other channels.

- **WorkflowPerturb: Calibrated Stress Tests for Evaluating Multi-Agent Workflow Metrics** — Kanda, Agarwal, Fonseca, Kumbhare, Las-Casas (Microsoft) · https://arxiv.org/abs/2602.17990
  Multi-agent systems that generate structured workflows from natural language are in production for cloud automation and DevOps, and routine changes (re-runs, model swaps, prompt refactors) produce workflows that drift from validated references without a principled shipping decision. WorkflowPerturb applies graded perturbations — Missing Steps, Compressed Steps, Description Changes at 10/30/50% severity — to 4,973 golden workflows, yielding 44,757 variants. It benchmarks metric families for sensitivity and calibration using expected score trajectories and instance-level alert rates. Public on Hugging Face. **Why it matters:** Gives change-management for agent workflows a calibrated yardstick so a metric drop maps to a known severity.

- **Can LLMs in Draft-Verify-Revise Pipelines Resolve Deictic Ambiguity?** — Ekekezie · https://arxiv.org/abs/2609.12162
  In draft-verify-revise orchestration, context cascades across three LLM stages and an expression like 'previous' can be resolved differently at each stage — a deictic shift. Using a synthetic dataset of 10 base examples in three conditions, six models from three providers were tested across 21 reasoning-effort configurations with sequential e-value testing. Balanced accuracy ranged from 0.156 (below chance) to near-perfect: GPT-5.2 climbed from 0.156 without reasoning to 0.942 at highest effort, while Gemini 3 Pro stayed above 0.94 at every level and beat GPT-5.2 xhigh at ~5% of the cost. Wrong verdicts tended to rely on surface cues rather than operational reasoning. **Why it matters:** Multi-stage pipelines silently break on reference ambiguity unless the revise stage has enough reasoning budget — a cheap-model, low-effort configuration can be both faster and safer.

- **AIM: A Privacy-Aware Interoperable Memory Framework for Multi-Agent Multi-User LLM Systems** — Johnson, Kumankumah, Chatterjee, Sathyamurthi et al. · https://arxiv.org/abs/2609.12320
  AIM is a unified memory framework for multi-agent, multi-user LLM systems that dynamically classifies information as private (scoped to one user) or public (shared by all) and enforces index-level access control so private memories are retrievable only by their owner. It ships with MUMBench, the first public dataset for evaluating retrieval, creation, update, and deletion of memory in a multi-user setting across four domains. Over three runs AIM reaches 96.0% visibility classification accuracy, 58.8% strict operation accuracy, and 70.5% state-aware operation accuracy. **Why it matters:** Shared organisational memory for agents needs per-user isolation baked into the index, not bolted on — and the operation-accuracy numbers show it is still far from solved.

- **UltraQuant: 4-bit KV Caching for Context-Heavy Agents** — Chakrabarti, Limpus, Rana, Bao, Tiwari, Crepaldi, Sirasao (AMD) · https://arxiv.org/abs/2606.20474
  Context-heavy agents reuse long prefixes across many short turns, so KV-cache residency and concurrency dominate serving throughput. The paper studies 4-bit KV compression for this regime with TurboQuant-style rotation/codebook quantization as the quality anchor and vLLM FP8 as the deployment anchor, detailing the design choices (asymmetric K/V treatment, Walsh-Hadamard rotation, QJL removal, block scales) that make the 4-bit path robust. UltraQuant, an FP4 path using FP8 queries, FP4 KV tensors, and native scaled-MFMA on CDNA4 AMD GPUs, sustains 2.71x (MiniMax-M2.5) and 4.38x (Qwen3-235B) the qualified-request throughput of BF16 on an adaptive-SLO replay of production Claude Code traces while using half the KV bytes of FP8. **Why it matters:** Agent serving is a distinct workload, and 4-bit KV cache is a large throughput lever precisely where long-context concurrency bites hardest.
