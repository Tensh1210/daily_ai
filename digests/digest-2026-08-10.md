## 📄 Research Papers — Top Picks
- **Capek 0.5: An Execution-Centric Vision-Language Model for Embodied Intelligence** — Ying Chen et al. (arXiv cs.AI) · https://arxiv.org/abs/2608.06756
  Capek 0.5 is a vision-language model built around the execution loop of embodied agents rather than around isolated perception or planning benchmarks. The authors argue robot execution is iterative — each action reshapes the scene, renewing what must be perceived, reasoned over, and verified — so the capabilities needed differ in supervision signal, output format, and verification criteria. The model organizes those complementary capabilities around execution as a whole instead of training each against a task-specific objective. **Why it matters:** Treating verification-after-action as a first-class training target is the piece most VLA stacks currently bolt on afterwards.

- **Science Edge Evaluation: SEE the Missing Step Toward Real Scientific Discovery** — Taolin Han et al. (arXiv cs.AI) · https://arxiv.org/abs/2608.06931
  SEE is a multimodal benchmark of expert-curated questions grounded in peer-reviewed literature and real lab practice across chemistry, biology, and materials science. Across 19 multimodal LLMs the best model reaches only 48.7% accuracy, and general-purpose models beat science-specialized ones on average. In the visual-agent setting, giving models tools raises the best score further. **Why it matters:** A sub-50% ceiling on grounded lab science is a concrete rebuttal to "AI scientist" claims, and shows tool access — not domain fine-tuning — is what moves the number.

- **Agent Memory Distillation: Empowering Small LLM Agents with Hierarchical Teacher Memory** — Taeil Kim, Kangsan Kim, Sung Ju Hwang (arXiv cs.AI) · https://arxiv.org/abs/2608.07169
  AMD is a training-free framework that transfers structured knowledge from a large teacher agent to a small student agent through hierarchical memory. From successful teacher trajectories it builds three memory types: workflow memory (task-level strategy), subtask memory (intermediate behavioral examples), and function memory (low-level procedural detail). This sidesteps the core problem that small models rarely generate enough successful trajectories to learn from themselves. **Why it matters:** A no-training path to make cheap models usable as agents, using memory as the distillation medium instead of weights.

- **Kimi K2.5: Visual Agentic Intelligence** — Kimi Team (arXiv cs.CL) · https://arxiv.org/abs/2602.02276
  K2.5 is an open-source multimodal agentic model that jointly optimizes text and vision via joint pre-training, zero-vision SFT, and joint text-vision RL. On top of that foundation it adds Agent Swarm, a self-directed parallel orchestration framework that decomposes tasks into heterogeneous sub-problems and runs them concurrently. The paper reports state-of-the-art results across agentic and multimodal evaluations. **Why it matters:** Open-weight models are now shipping built-in multi-agent orchestration rather than leaving it to the harness.

- **HLSmith: An Expert-Guided Agentic Framework for C/C++-to-HLS Translation** — Yuebo Luo et al. (arXiv cs.AI) · https://arxiv.org/abs/2608.06791
  HLSmith targets the gap where frontier LLMs can write software but lack the hardware intuition to turn baseline C/C++ into high-performance HLS designs for FPGA accelerators. The framework injects expert procedural knowledge to guide architecture selection and optimization steps that models otherwise skip or misapply. It addresses a domain where hand-development typically costs months of specialized effort. **Why it matters:** Encoding domain procedure as agent scaffolding is the practical alternative to waiting for models to acquire hardware intuition.

- **The Horizon Gap: Planning, Memory, Execution, Training, and Evaluation for Long-Horizon LLM Agents** — Mingguang Chen, Licheng Wang, Bo Qu (arXiv cs.CL) · https://arxiv.org/abs/2608.06663
  A survey of 1,547 arXiv papers (2024–2026) on why frontier models solve hard single-pass reasoning yet fail multi-hour tasks — losing earlier decisions, declaring half-finished work done, drifting from goals. Its main contribution is disambiguating three routinely conflated properties: long-horizon (task: steps required), long-context (model: token capacity), and long-term memory (system: persistence across steps and sessions). Methodology is disclosed, including a 26.8% bleed filter on the seed harvest. **Why it matters:** The conflation of context length with horizon capability is the most common source of bad agent-architecture decisions.

- **SkillProx: Self-Evolving Agent Skills via Proximal Textual Gradient Descent** — Mingxuan Zheng et al. (arXiv cs.CL) · https://arxiv.org/abs/2608.07449
  SkillProx refines an agent's textual skill library with a proximal-gradient-inspired forward–backward loop that couples closed-loop diagnosis to skill edits. Unlike prior methods, it treats deletion as a dedicated consolidation mechanism rather than a generic edit, and ties each update to explicit diagnosis–outcome feedback. Skills stay lightweight context artifacts — no weight updates. **Why it matters:** Skill libraries grow monotonically without a real eviction rule; making deletion first-class is the fix.

- **Ratchet: How Reliable Must an LLM Judge Be to Retire a Skill?** — Xing Zhang et al. (arXiv cs.CL) · https://arxiv.org/abs/2605.22148
  The paper gives an exact threshold: a judge that scores failures as passes at rate (1−τ)/2 or above retires nothing, at any sample size, for eviction margin τ. Audits find LLM-written skills are worth +0.0pp against a no-skill control while human-written ones are worth +16.2pp, and unmaintained libraries suffer "library drift" until injecting a skill is worse than injecting nothing. Ratchet supplies the eviction machinery. **Why it matters:** Hard evidence that self-authored skill libraries are net-zero without a judge reliable enough to delete.

- **Skill-RAG: Failure-State-Aware Retrieval Augmentation via Hidden-State Probing and Skill Routing** — Kai Wei et al. (arXiv cs.CL) · https://arxiv.org/abs/2604.15771
  Skill-RAG argues most persistent retrieval failures are not missing evidence but an alignment gap between the query and the evidence space, which existing adaptive-retrieval systems answer by retrying rather than diagnosing. It couples a lightweight hidden-state probe to detect the failure state with skill routing to pick a corrective strategy. **Why it matters:** Shifts RAG failure handling from blind retry to diagnosis, which is where most production RAG latency is wasted.

- **LiveMem: Maintaining Memory State Continuity in Long-Running LLM Inference** — Zhichen Liu et al. (arXiv cs.CL) · https://arxiv.org/abs/2608.02515
  LiveMem formalizes "state continuity under context turnover": carrying computation forward through a fixed-capacity memory state whose lifetime is independent of the active context window. It augments a pretrained full-attention LLM with an intrinsic memory state, rather than relying on summarization or retrieval over selected history. Target setting is assistants and agents whose interaction streams outgrow any context. **Why it matters:** Retrieval preserves access to old text but not accumulated computation — this attacks the harder half of the memory problem.

- **From Plan to Action: How Well Do Agents Follow the Plan?** — Shuyang Liu et al. (arXiv cs.CL) · https://arxiv.org/abs/2604.12147
  The first systematic study of plan compliance in programming agents, over 21,120 SWE-agent trajectories across four LLMs on SWE-bench Verified and SWE-bench Pro under eight plan variations. The question is whether solved tasks reflect correct strategic reasoning or contamination/benchmark overfitting, which is unanswerable without measuring compliance. **Why it matters:** If agents ignore the plans they're given, plan-quality work and benchmark scores are both measuring the wrong thing.

- **OpenForgeRL: Train Harness-native Agents in Any Environment** — Xiao Yu et al. (arXiv cs.CL) · https://arxiv.org/abs/2607.21557
  Modern agents run inside elaborate harnesses (Claude Code, Codex, OpenClaw) whose stateful multi-process inference open SFT/RL stacks cannot natively express, making end-to-end training hard. OpenForgeRL inserts a lightweight proxy that serves the harness's model calls while recording them as standard training data. Result: harness-based agents trainable end-to-end across diverse environments. **Why it matters:** Lets teams train against the harness they actually ship, instead of a simplified training-time approximation of it.

- **WebGrader: Training LLMs for Web Development with Self-Evolving Programmatic Grader** — Boshui Chen, Huiping Liu, Shaolei Zhang (arXiv cs.AI) · https://arxiv.org/abs/2608.06474
  RL for website generation is bottlenecked by reward design: hand-authored browser scripts are executable but expensive, while VLM/GUI-agent graders scale yet often judge before the decisive state appears. WebGrader derives the required interaction flows from each website request, encodes each as an executable Flow Contract, and grades against it. **Why it matters:** Moves web-agent rewards from "looks right" screenshots to executable contracts on actual interaction state.

- **Long-Horizon Agent Trajectory Attribution: A Unified Benchmark and Fine-Grained Annotation Framework** — Jing Chen et al. (arXiv cs.AI) · https://arxiv.org/abs/2608.06909
  Existing agent benchmarks score outcomes but say little about which component caused a failure. This work defines trajectory attribution and ships a benchmark plus annotation framework organizing heterogeneous trajectories (instructions, tool calls, observations, memory) under one component schema, labeling the primary attribution component along with attack and execution chains. **Why it matters:** Component-level attribution is the missing instrument for debugging agents whose failures are currently only visible as a final wrong answer.

- **Coupling Planning with Episodic Memory in LLM Agents for Software Issue Resolution** — Jiahao Zhang, Yifan Zhang, Yu Huang (arXiv cs.AI) · https://arxiv.org/abs/2608.06811
  PMCoder targets long repair episodes — tens to hundreds of steps across exploration, hypothesis, implementation, and verification — where repo-level agents typically strengthen planning or memory in isolation. Coupling the two guards against stale evidence, repeated failed edits, and verification inferred from the agent's own claims instead of execution evidence. **Why it matters:** Names the specific failure mode (self-reported verification) that makes long agent runs look successful while being wrong.
