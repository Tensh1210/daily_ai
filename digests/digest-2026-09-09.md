## 📄 Research Papers — Top Picks
- **ASDA: Automated Skill Distillation and Adaptation for Financial Reasoning** — Yim, Tan, Chan, Lam, Yiu · https://arxiv.org/abs/2603.16112
  ASDA generates structured skill artifacts through iterative error-corrective learning without modifying model weights. A teacher model analyzes a student's failures on financial reasoning, clusters errors by subfield and error type, then synthesizes skill files containing reasoning procedures, code templates, and worked examples. The authors show leading training-free methods (GEPA, ACE) gain only marginally on the FAMMA benchmark, exposing the limits of unstructured text optimization. **Why it matters:** Structured, file-based skills beat free-text prompt optimization for multi-step domain reasoning — and stay portable across models.

- **AgentBrew: Offline Tool-Use Agent Learning from Raw Real-World Trajectories** — Lyu, Li, Zheng, Yang, Feng et al. · https://arxiv.org/abs/2609.05837
  AgentBrew trains tool-use policies from a single batch of raw, unfiltered interaction trajectories — no task verifiers, no faithful simulators, no iterative on-policy rollouts. Retrospective task inference reconstructs an aligned instruction for each trajectory from its actual outcome, and PMI-based credit assignment extracts training signal from the noisy corpus. This targets the realistic case where a deployed tool API offers no predefined tasks or reward. **Why it matters:** Most production agent environments have logs but no verifier; learning offline from those logs is the practical training path.

- **ZhuLong: Execution-Grounded LLM Agent for EDA Scripting with Offline API Self-Exploration** — Liu, Hou, Chen, Wang, Yuan et al. · https://arxiv.org/abs/2608.07925
  ZhuLong is a coding agent for PyAether and SKILL that combines API retrieval, documentation inspection, and sandbox execution behind unified MCP tools. An offline self-exploration mechanism infers undocumented API behavior through counterfactual experimentation. On EDA-Eval-PyAether (158 real tasks with assertion-based execution) it reaches 78.5% Pass@1 versus 23.6% for a pure LLM baseline; ablations attribute 41.2 points to sandbox execution. **Why it matters:** Quantifies what actually drives agent coding performance on undocumented APIs — execution grounding dominates, retrieval alone does not.

- **Substrate-Portable Execution for Production LLM Workflows** — Gopinath, Kulkarni, Rajakumar, Katti, Govindarajen · https://arxiv.org/abs/2609.06128
  From Amazon's Rufus assistant: a binding-adaptive agent execution platform that separates workflow definition from execution substrate. The same tool-calling loop or retrieval chain runs in real-time serving, asynchronous background, and high-volume batch modes without a per-mode rewrite. Reusing streaming orchestration for batch makes those workloads blocking and blocks use of batch inference APIs, which are 50% cheaper at published prices. **Why it matters:** Decoupling agent logic from runtime unlocks batch pricing and removes a common source of duplicated production agent code.

- **Inference-Time Graph Engineering for Multi-Agent LLM Workflows** — Tieu, Fu, Xia, Li, Yan, He · https://arxiv.org/abs/2609.05774
  ReActNet is a training-free framework that compiles a query plus a set of role-specialized agents into a sequence of directed communication graphs, one snapshot per reasoning stage. Each edge carries a natural-language instruction specifying what the source agent must pass to the target, and the compiled temporal graph is executed by structured message passing. Topology is synthesized per task rather than fixed in advance. **Why it matters:** Treats multi-agent orchestration as a task-conditioned artifact to compile, not a static architecture to hand-design.

- **Environments as Scaffold: Enriching Feedback to Bootstrap Self-Evolving Agents in Long-Horizon Tasks** — Yuan, Jin, Cao · https://huggingface.co/papers/2609.08404
  Rather than warming up the agent with SFT, this work adapts the environment: Feedback-Enriched Environments (FEEs) attack the severe reward sparsity of long-horizon agent RL. A pilot study yields a feedback design strategy that shifts from action guidance to observation enrichment in the later stages of both intra-episode exploration and inter-episode evolution. Large-scale experiments cover SciWorld and BFCL across Qwen3 scales with GRPO, GSPO, and DAPO. **Why it matters:** Fixing the environment's feedback channel may be cheaper and more general than collecting agent-side SFT data.

- **NeoHorse-1: Towards Recursive Self-Improvement via Agentic Post-Training with Routing Harness** — NeoHorse Team · https://huggingface.co/papers/2609.08183
  NeoHorse-1 is a family of agent-native models built on a heterogeneous model pool with intelligent routing. Every user turn records predicted capability demand, selected service tier, and the resulting interaction; those records become training examples preserving interleaved reasoning, tool calls, and harness context. Admission runs through structural validation, six-dimensional semantic evaluation, and subscene-level labeling, then feeds a three-stage SFT curriculum and routing-guided on-policy distillation. **Why it matters:** Makes the serving router itself the data-collection mechanism, turning production traffic into a self-improvement loop.

- **PARSER: Read in Parallel, Reason in Depth for Long-Context LLM Agents** — Li, Qiu, Zhang, King, Meng · https://arxiv.org/abs/2609.06702
  PARSER decouples document reading from reasoning. A bank of lightweight subagents, each bound to a single chunk, reads the whole document in parallel while a lead agent runs iterative scatter–gather rounds: broadcast a query, aggregate returned evidence, formulate a deeper follow-up conditioned on findings. All learnable behavior sits in the lead agent, optimized with RL, while subagents stay frozen. **Why it matters:** Breaks the linear latency and evidence-placement sensitivity of sequential memory agents on long documents.

- **When Does Memory Help? A Cost-Aware Evaluation of Long-Term Memory in Tool-Using LLM Agents** — Mishra, Mishra · https://arxiv.org/abs/2609.05441
  MERIT measures the marginal utility of memory for task-executing agents rather than conversational recall. It provides episodic tool-use tasks in three domains with automated leak checks, a difficulty ladder ending in updated-fact recall, controlled memory corruption, and full token and dollar metering of every memory operation. Results span 23,440 scored episodes across a gpt-4.1-mini pilot and a preregistered 3-model × 3-seed grid including GPT-4.1 and Claude. **Why it matters:** Existing memory benchmarks score recall; this one asks whether remembering changes what the agent does, and at what cost.

- **SkillAlign: Aligning Skill Interfaces for LLM-based Agents** — Ren, Kang, Zhang · https://arxiv.org/abs/2609.07255
  SkillAlign argues skill utility depends on how a skill is exposed, not only which skill is selected. It represents candidate skills as multi-view procedural cards rendered through alternative exposure interfaces — full instructions, hints, compressed summaries, workflows, or no exposure — enabling counterfactual evaluation where task, agent, and candidate skills are fixed and only the interface varies. Evaluation spans ALFWorld and a skills benchmark. **Why it matters:** The same skill file can help, distract, or mislead depending on presentation; that variable has been largely unmeasured.

- **SkillSpec: Intent-Masked Specification Reasoning for Agent Skill Correctness** — Zhang, Kang, Yang, Duan, Ye, Yang · https://arxiv.org/abs/2609.06052
  SkillSpec formulates skill correctness as a Hoare-style specification reasoning problem. It transforms a heterogeneous skill repository into a unified graph aligning descriptions, instructions, and code artifacts, then derives specifications per node. The target failure modes are semantic rather than syntactic: intent conflicts that manifest as silent failures masked by the underlying model. **Why it matters:** Skill bundles mixing prose and code have no compiler; specification reasoning is a route to catching intent drift before deployment.

- **Learning to Configure Agentic AI Systems** — Taparia, Sagar, Senanayake · https://arxiv.org/abs/2602.11574
  Agent configuration — workflow, tools, token budgets, prompts — is framed as a semi-Markov decision process where each configuration is a temporally extended option. ARC (Agentic Resource & Configuration learner) is a lightweight hierarchical policy that selects a query-specific configuration instead of applying one fixed template regardless of difficulty. Across reasoning, tool-use, and agentic benchmarks it consistently beats budget-matched tool-augmented LLMs. **Why it matters:** Replaces hand-tuned heuristics over the combinatorial agent design space with a learned policy, at matched compute.

- **RedEvoAgent: Automatic Red-Teaming Agent with Experience-Driven Skill Evolution** — Zhang, Liu, Chen, Mo, Chen, Li · https://arxiv.org/abs/2608.27439
  RedEvoAgent is a black-box red-teaming agent that distills cross-case attack trajectories into a concise, human-readable attack skill, which then evolves via tool-effectiveness profiling and deciding-tool attribution. This avoids the retrieval bias and context overhead of reusing full trajectories. The threat model is jailbreaks inside product-level execution harnesses, where an attack triggers harmful tool use and persistent state changes. **Why it matters:** Agent jailbreaks cause real side effects, not just bad text — red-teaming has to target the harness, not the chat box.

- **Omni Interaction Agent Technical Report (Gander)** — Ji, Tong, Zuo, Fu, Cao et al. · https://huggingface.co/papers/2609.08977
  Gander is an end-to-end model unifying omni perception, realtime interaction, and agentic capability in a single framework. It continuously consumes streaming video, speech, and text for full-duplex interaction: users can interrupt at any time, and the model can proactively offer intermediate feedback or ask follow-up questions. Architecturally it splits a Cerebellum handling realtime interaction and omni conversation from a Brain handling complex reasoning and higher-level agentic tasks. **Why it matters:** Full-duplex streaming plus agentic tool use in one model breaks the turn-based assumption most agent harnesses are built on.

- **Beyond Fluent Generation: A CPU Reliability Benchmark for MCP-Style Tool Calling in Sub-2B Small Language Models for Edge Deployment** — Mastoi · https://arxiv.org/abs/2609.07370
  A platform-agnostic CPU baseline for MCP-style tool invocation across five sub-2B open-weight models (Phi-1.5, Pythia-1.4B, TinyLlama-1.1B-Chat, Qwen2.5-0.5B, Qwen2.5-1.5B) on 100 prompts spanning weather retrieval, web search, calculation, email composition, and task creation. Scoring goes past fluency to machine-readable JSON, correct tool selection, complete required arguments, and absence of unintended actions, under both greedy and nucleus decoding. The target deployments are single-board computers such as Raspberry Pi, Jetson Nano, and Orange Pi. **Why it matters:** On-device MCP agents need reliability numbers, not fluency scores — this sets a reproducible CPU baseline.
