## 📄 Research Papers — Top Picks
- **VideoGen-Agent: Reinforcing Video Generation Agents** — HF Papers · https://huggingface.co/papers/2609.24997
  Video generators still fail on prompts needing specialised knowledge, identity preservation, physical consistency or ordered events. VideoGen-Agent is a multimodal agent trained with SFT on teacher trajectories and then multitask agentic RL to coordinate augmentation, generation and verification tools over multiple turns, with a category-aware hybrid reward covering tool-call validity, tool appropriateness and video quality. On the new 600-prompt VABench it lifts the base T2V model from 56.5 to 75.6, and swapping in better generation tools pushes it to 86.1 with no retraining. **Why it matters:** The agent policy transfers across tool upgrades — a clean argument for training the orchestrator rather than the generator.
- **Toollery: Scaling LLM Agents to Thousands of Skills and Tools** — arXiv cs.CL · https://arxiv.org/abs/2609.22218
  Full-library prompting breaks down once an agent has thousands of skills/tools: more tokens, more latency, more distractors. Toollery is a training-free candidate-compression layer that generates user-intent queries from each skill/tool spec, indexes them, and maps real requests to a compact top-k set before the LLM picks. Evaluated on the ~79K-capability SkillRouter benchmark, BFCL-V4 (440+ tools) and 3,396 proprietary smart-cockpit requests, it improves recall over plain spec retrieval while keeping AST accuracy comparable. **Why it matters:** Directly addresses the MCP/skill-registry scaling problem with a drop-in retrieval index instead of fine-tuning.
- **Harness-Zero: Harness Distillation via Agent-as-Harness** — HF Papers · https://huggingface.co/papers/2609.24974
  Agent harnesses (prompts, control flow, tooling) give big gains but only while deployed, and the best harness varies by domain and model. Harness-Zero distills an optimised harness into model weights: a "harnessing agent" guided by the optimised harness corrects student responses inside the target harness's action space, producing training demonstrations; fine-tuning on those trajectories internalises the behaviour so the specialised harness can be dropped at deployment. Tested across knowledge work, tool use and science domains. **Why it matters:** Lets you ship one simple harness while keeping the wins from many specialised ones.
- **RRSI: Regularized Recursive Self-Improvement of Agent Harnesses** — HF Papers · https://huggingface.co/papers/2609.24972
  Automated harness evolution (iteratively proposing and selecting edits to prompts, tools, memory, context management) tends to overfit training tasks, with gains that vanish out of distribution. RRSI adds regularisation: the proposer works under a temporally annealed edit budget and is pushed toward unexplored trajectories, while the selector uses a critic to screen benchmark-specific proposals and a pruner to drop tiny, expensive or stale changes. Across eight coding, agentic-workspace and engineering-design benchmarks it gains up to 14.1 points. **Why it matters:** Companion to Harness-Zero — makes self-evolving harnesses produce reusable mechanisms rather than benchmark hacks.
- **A Survey of Agentic Reasoning for Large Language Models: Towards Recursively Self-Improving and Collective Agents** — arXiv cs.CL · https://arxiv.org/abs/2601.12538
  Organises agentic reasoning along three layers — foundational (planning, tool use, search in stable environments), self-evolving (feedback, memory, adaptation) and collective multi-agent (coordination, knowledge sharing) — and cross-cuts them with in-context reasoning via orchestration versus post-training via RL/SFT. Reviews frameworks and benchmarks across science, research and real-world applications. **Why it matters:** A useful map for placing this week's harness/memory/skill papers in a single taxonomy.
- **FLARE: A Full-Lifecycle Dense Supervision Paradigm for Long-Horizon Coding Agents via Generative Reward Model** — arXiv cs.CL · https://arxiv.org/abs/2609.23808
  Sparse pass/fail rewards waste failed SWE trajectories and make credit assignment hard. FLARE distils a lightweight Generative Reward Model from RADAR, an offline causal-chain backtracking diagnostic, giving step-level risk feedback. At inference the GRM acts as an active scaffold that intercepts high-risk steps for localised breakpoint re-execution; in post-training its signals become reranking scores for SFT and dense step rewards for RL. **Why it matters:** One reward model serving both test-time scaffolding and training is a cheap way to stabilise coding agents.
- **Jev-Mem: System-One-Controlled Agentic Memory for Efficient AI Agents** — HF Papers · https://huggingface.co/papers/2609.23986
  Most agentic memory systems put an autoregressive LLM on the critical path of every memory operation. Jev-Mem splits the work: a fast System-One controller handles memory typing, relational organisation, query routing, retrieval-budget allocation, graph traversal, candidate scoring and adaptive stopping; a System-Two LLM is invoked only for complex reasoning and answer synthesis. On LoCoMo it reaches a 0.777 LLM-judge score (+11% relative), builds memory 6.6x faster (158 s) and cuts query latency 36.7% to 0.93 s. **Why it matters:** Shows most memory plumbing does not need an LLM, which is where the latency and cost were going.
- **AgentRouter: Heterogeneous Model Routing for Cost-Optimal Multi-Step Agentic Workflows** — arXiv cs.CL · https://arxiv.org/abs/2609.22951
  Routing every trajectory step to a frontier model wastes 60–80% of budget on subtasks small models handle fine. AgentRouter formalises step-level routing as sequential assignment and trains a 12M-parameter classifier (<5 ms/step) on 50K annotated steps to map each step to one of four model tiers. It cuts cost 72% while retaining 97.3% of frontier-only quality; per-step RouteLLM and FrugalGPT reach only 31% and 44% savings. **Why it matters:** Step-level, not query-level, routing is the right granularity for agent workflows, and this quantifies the gap.
- **Semantics Delivery Network: Rethinking Web Retrieval Infrastructure for LLM Agents** — arXiv cs.IR · https://arxiv.org/abs/2609.22486
  Web search and CDNs are built for human clients: URL lists, snippets and URL-addressed cached objects. Agents instead consume short task-relevant chunks and retrieve statefully across turns, and uncoordinated agents duplicate acquisition and processing. SemDN proposes an origin-authorised hierarchical edge substrate that indexes, searches and smart-caches web content at chunk granularity on behalf of participating sites, with tenant-specific retrieval policies. **Why it matters:** A position paper, but it names the infrastructure gap every agentic-RAG deployment hits when scaling.
- **Machine-Interpretable Information: Compiling Documents into Searchable and Readable Protocol States** — arXiv cs.CL · https://arxiv.org/abs/2609.23371
  RAG suffers an index–payload split: vectors route but the model still re-ingests full text at O(N²) attention cost. MII compiles a document into a fixed 56-token state via a dual-timescale state-space Writer, and a lightweight Translator maps it into any frozen Reader's embedding space, reducing query-time cost to O(K). The .mii artifact serves retrieval, reasoning and reconstruction, and transfers across Llama, Qwen and Mistral; probes show entity representations can be transplanted between document states. **Why it matters:** An agent-to-agent document protocol that is model-agnostic would change how context is shared between heterogeneous agents.
- **Divide by Question, Conquer by Agent: SPLIT-RAG with Question-Driven Graph Partitioning** — arXiv cs.IR · https://arxiv.org/abs/2505.13994
  Monolithic graph retrieval adds latency for simple queries and fragments reasoning on multi-hop ones. SPLIT-RAG partitions the knowledge graph into semantically coherent, type-specialised subgraphs aligned with query types, assigns lightweight LLM agents to partitions, activates only relevant ones per query, and merges subgraph answers through a hierarchical logical-verification step. **Why it matters:** A concrete recipe for making graph-RAG scale by routing to partitions rather than searching everything.
- **Behavioral Skill Reconstruction: Reconstructing Hidden Functionality from LLM Agent Skills** — arXiv cs.CL · https://arxiv.org/abs/2608.04192
  Closed-source agent skills hide instructions, scripts and data, and defences focus on preventing file disclosure. SkillClone shows that is not enough: a black-box attacker forms an interface hypothesis from the skill's public advertisement, sends structured benign probes, synthesises an executable replica and repairs it via differential validation against the victim. Across 30 skills covering rules, tables, procedures and algorithms it achieves exact or partial recovery on several targets. **Why it matters:** If you sell skills as a service, functional cloning through normal use is a threat that prompt-injection defences do not cover.
- **BabelArena: A Large-Scale Multilingual Benchmark for LLM Agents** — arXiv cs.CL · https://arxiv.org/abs/2609.23490
  BabelFlow adapts existing agent benchmarks to new languages by analysing runtime dependencies, doing structure-preserving translation and verifying with multi-layer checks plus human review. The resulting BabelArena has 16,146 instances from 702 tasks across four benchmark families, 13 domains and 23 languages. Five frontier models show no single winner, and low-resource languages produce more tool-use and control-flow errors (not just answer errors) while consuming up to ~2x the input tokens. **Why it matters:** Agent reliability, not just answer quality, degrades outside English — relevant for anyone shipping agents to Vietnamese or other non-English users.
- **Canonical Procedural Actions: An Auditable Annotation Protocol for Tool-Use Agent Traces** — arXiv cs.CL · https://arxiv.org/abs/2609.24264
  Agent traces record messages and API calls, but procedural analysis needs explicit action units linked to evidence. CPAs annotate a procedural function, its first agent-event anchor, the realising events and separate contextual evidence. A retail case study builds a versioned 24-entry codebook; two isolated LLM annotators on 32 held-out trajectories reach anchor-label overlap of 0.982 (0.798 when identical evidence references are required), and the frozen codebook applied to 244 more trajectories yields 4,058 records. **Why it matters:** A repeatable way to turn raw tool-call logs into auditable action data for evals and post-mortems.
- **Strategy Accumulation and Guided Execution for Automated LLM Fine-Tuning** — arXiv cs.CL · https://arxiv.org/abs/2609.22257
  Automated fine-tuning searches are stateless — every new task restarts from cold. SAGE runs a multi-agent MCTS exploration while a parallel Distillation Agent extracts task-specific records and confidence-scored cross-task insights into an experience repository; on a new task it retrieves and applies relevant experience to guide training. On nine unseen tasks, accumulated experience raises average relative improvement over baseline from 3.2% to 15.6%. **Why it matters:** Persistent experience memory for AutoML-style agents, with a measurable gain from remembering past searches.
