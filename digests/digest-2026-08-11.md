## 📄 Research Papers — Top Picks
- **Stealing Reasoning Traces from Proprietary LLM APIs** — Alexander Panfilov et al. (arXiv cs.AI) · https://arxiv.org/abs/2608.09867
  Providers hide chain-of-thought by returning it to the client as encrypted blocks that get passed back on each request. The authors find these blocks are interchangeable across sessions, users, and models within one provider, and exploit that by injecting a strong model's encrypted trace into a weaker, less-safeguarded sibling that decodes it verbatim in plaintext. Demonstrated against Anthropic, OpenAI, and Google. Decoding 315,320 blocks scraped from public repos recovered 367 PII artifacts and 182 credentials. **Why it matters:** Encrypted reasoning blocks in shared session logs are a live credential-leak channel, not just an IP concern.

- **DarwinX: Evolving Agent Harnesses Through Natural Selection** — Yifan Zhang et al. (arXiv cs.AI) · https://arxiv.org/abs/2608.07545
  DarwinX treats self-improvement as population-level selection over agent harnesses (prompts, tools, skills, control flow) with the model weights frozen, instead of single-lineage editing that is path-dependent and regresses other tasks. A preserve-and-extend contract admits only variants that extend coverage without regression, and an archive keeps alternative lineages for recombination; fitness comes from each benchmark's own verifier. One loop adds ~17 points on average, pushing Terminal-Bench 2.1 to 84.7% and WebArena-Infinity pass@1 from 43.5% to 93.0%, and a harness transfers unchanged to SWE-bench Verified. **Why it matters:** Evidence that harness search converts eval compute into durable, transferable capability without touching weights.

- **Evo-Bench: Can Language Models Improve Agent Harness?** — Lisheng Huang et al. (arXiv cs.CL) · https://arxiv.org/abs/2608.09096
  The first benchmark aimed squarely at harness evolution — whether a model can optimize its own operating harness — across Search, Office, and General domains. It isolates harness gains from base-model strength via auxiliary-task evolution to find framework-sensitive tasks, then sensitivity-aware stratified splitting for cross-suite generalization. Across nine frontier and open-weight models, top models gain up to 16.6 points, approaching human-engineered baselines; autonomous evolution beats hand-built harnesses on General and Search but struggles on Office tasks needing specific workflows. **Why it matters:** Gives a measurable answer to whether self-improving harnesses beat hand-tuning, and where they don't.

- **Motif 3: Technical Report** — Junghwan Lim et al., Motif (HF Papers / arXiv cs.AI) · https://huggingface.co/papers/2608.09119
  A decoder-only MoE with 314B total / 13.2B active parameters, 384 routed experts per layer with eight selected per token. Built on Grouped Differential Latent Attention (grouped differential attention plus MLA's compressed KV), with manifold-constrained hyper-connections, Expert-Specific PolyNorm, and multi-token prediction. Pretrained on ~12.5T tokens with selective MXFP8 and window-aware context parallelism to reach 256K context; post-training combines general SFT, six RL-trained specialist teachers, an SFT software-engineering teacher, and multi-teacher on-policy distillation. **Why it matters:** Multi-teacher on-policy distillation into one unified model is becoming the standard recipe for consolidating specialist capability.

- **SkillSentry: Reliable Skill Execution for LLM Agents via Runtime Assurance** — You Lu, Xinyu Huang, Bihuan Chen, Xin Peng (arXiv cs.AI) · https://arxiv.org/abs/2608.09253
  Agents that provably *can* follow a skill still deviate or misexecute steps across similar tasks and repeated runs. SkillSentry defines a DSL for runtime guidance, seeds it from the skill document plus mined successful/failed traces, then wraps the agent loop to monitor and steer execution while refining guidance from new traces. Evaluated on 15 skills across Claude Code (Haiku 4.5, Opus 4.6) and Codex (GPT-5.2, GPT-5.4), it raises task success by 24.1% on average. **Why it matters:** Skill *reliability under repetition* — not skill authoring — is the current bottleneck, and this measures it directly on shipping harnesses.

- **ColluSkill: Adversarial Cross-Skill Composition for Evading Agent Skill Scanners** — Puyu Zeng et al. (arXiv cs.AI) · https://arxiv.org/abs/2608.09732
  Existing skill scanners inspect skills one at a time, so several individually plausible skills can each pass review yet form a harmful workflow when composed. ColluSkill splits a malicious intent into interdependent sub-payloads across separately packaged skills, linked by contextual dependencies, artifact passing, and execution handoffs, with LLM chain planning and scanner-feedback refinement to suppress per-skill signals. The authors also propose ChainGuard, a context-aware scanner that reconstructs cross-skill dependency and artifact flows against already-installed skills. **Why it matters:** Per-skill scanning is structurally insufficient once agents install skills from multiple sources.

- **Query-Only Backdoor Attacks on Self-Evolving Skills via Trajectory Poisoning** — Yuyang Luo, Haoran Wang, Kai Shu (arXiv cs.AI) · https://arxiv.org/abs/2608.08303
  Self-evolving skill systems were meant to reduce exposure by replacing untrusted marketplace skills with internally constructed ones. TBA shows the evolution pipeline itself is an attack surface: an attacker submits only ordinary queries, crafted so the agent performs a target action and states its activation condition in the trajectory, repeating the condition–action pattern across triggered tasks while leaving clean queries untouched. The evolver then consolidates the pattern into a trigger-dependent rule inside an evolved skill. **Why it matters:** "Trusted internal skill construction" is not a security boundary if untrusted users can shape the trajectories it learns from.

- **TraceSafe: A Systematic Assessment of LLM Guardrails on Multi-Step Tool-Calling Trajectories** — Yen-Shan Chen et al. (arXiv cs.CL) · https://arxiv.org/abs/2604.07223
  As the vulnerability surface moves from final outputs to intermediate execution traces, TraceSafe-Bench benchmarks mid-trajectory safety over 12 risk categories and 1,000+ execution instances, evaluating 13 LLM-as-a-guard models and 7 specialized guardrails. Findings: guardrail efficacy tracks structural data competence like JSON parsing (ρ=0.79) rather than jailbreak robustness; detection accuracy does not scale monotonically with model size; and general-purpose LLMs consistently beat specialized safety guardrails. **Why it matters:** Teams picking a "safety model" for agent traces are optimizing the wrong axis — parsing competence predicts performance, alignment tuning doesn't.

- **Reason Wide, Not Deep: Amortizing the Reasoning Premium into Distilled Skills** — Agamdeep Singh et al. (arXiv cs.AI) · https://arxiv.org/abs/2608.07885
  Reasoning modes beat non-reasoning ones on agentic tasks but cost 3–6x output tokens per episode, much of it re-deriving procedures shared across episodes in the same domain. A coding agent analyzes a small trajectory corpus and compiles a compact natural-language skill into the non-reasoning model's system prompt. Across ALFWorld, τ²-bench (telecom, retail), and SpreadsheetBench-Verified, skills recover 55–100%+ of the reasoning gap for GPT-5.4-mini on held-out tasks — beating reasoning mode outright on two of four — with 2.7–6x fewer output tokens and zero reasoning tokens. Skills distilled from non-reasoning trajectories alone stay competitive. **Why it matters:** Reframes skills as amortized search: pay once across a corpus instead of every episode, with a clean token-cost number attached.

- **FailForge: Distilling Procedural Competence from Persistent Failures into Code Agents** — Dongyi Lv et al. (arXiv cs.AI) · https://arxiv.org/abs/2608.08570
  Rejection-sampling fine-tuning discards failed rollouts — precisely the hardest, most informative instances on expensively curated verifiable tasks. FailForge has an agent diagnose each failure from error feedback and execution traces, distill the diagnosis into a concise skill, inject it for a guided second attempt, and fold newly successful trajectories back into the RFT corpus. The skill is stripped at training time so the model internalizes the behavior rather than depending on the hint. It recovers 26%+ of previously failed instances and improves Qwen3.5-4B on SWE-bench Verified by 6.6 points over a strong RFT baseline. **Why it matters:** Turns the discarded half of RFT into training signal, with gains concentrated exactly on the hard frontier.

- **InfMem: Learning System-2 Memory Control for Long-Context Agent** — Xinyu Wang et al. (arXiv cs.CL) · https://arxiv.org/abs/2602.02704
  Streaming agents scale to long documents but their passive memory updates drop low-salience bridging evidence that multi-hop reasoning needs. InfMem makes memory control explicit via a PreThink–Retrieve–Write protocol: monitor evidence sufficiency, do targeted in-document retrieval, and apply evidence-aware joint compression into bounded memory, trained with an SFT-to-RL recipe that aligns retrieve/write/stop decisions with end-task correctness. On 32k–1M-token QA it beats MemAgent by 8–12 accuracy points across three backbones while cutting inference time 3.9x on average via adaptive early stopping. **Why it matters:** Accuracy and latency improving together is unusual — the win comes from knowing when to stop, not from a bigger memory.

- **SkillReason: Reasoning-Enhanced Agent Skill Retrieval for Implicit User Requests** — Donghong Jiang et al. (arXiv cs.AI) · https://arxiv.org/abs/2608.08640
  Real user requests state a goal and leave required capabilities and steps implicit, which breaks retrieval over large skill libraries. SkillReason-Bench supplies 3,729 queries against a 61,228-skill corpus across nine domains. The method uses teacher-generated capability-reasoning traces as training-time supervision (contrastive learning, retrieval-distribution alignment, language modeling), then a retrieval-guided GRPO stage; at inference it encodes the raw query directly with no autoregressive CoT, preserving cheap query-only retrieval. **Why it matters:** Puts the reasoning cost in training rather than in every retrieval call — the right trade for skill libraries at 60k scale.

- **ZhuLong: Execution-Grounded LLM Agent for EDA Scripting with Offline API Self-Exploration** — Yang Liu et al. (arXiv cs.AI) · https://arxiv.org/abs/2608.07925
  Chip-design scripting depends on tool-specific, largely undocumented APIs that LLMs cannot cover. ZhuLong combines API retrieval, doc inspection, and sandbox execution behind unified MCP tools, plus offline self-exploration that infers undocumented API behavior through counterfactual experiments. On EDA-Eval-PyAether (158 real tasks, assertion-based) it hits 78.5% Pass@1 versus 23.6% for a pure LLM baseline; ablations attribute 41.2 pp to sandbox execution, with self-exploration adding 3.2 pp and cutting tool calls 22.1%. **Why it matters:** The ablation is the finding — execution grounding, not retrieval or prompting, is what carries undocumented-API domains.

- **OpenVisTool: An Open Recipe for Synthesizing Instructive Visual Tool-Use Trajectories** — Changhao Xiang et al. (arXiv cs.CL) · https://arxiv.org/abs/2608.08557
  Standard practice trains visual tool use on teacher trajectories filtered only for answer correctness, but a strong teacher often reaches the answer without needing its tool calls — teaching the student that tool calls *accompany* correct answers rather than ground them. OpenVisTool keeps a trajectory only if the answer is correct *and* the tool observations causally contributed, via difficulty screening, domain-specific synthesis, and supervision verification. The result is OpenVisTool-42K across five visual reasoning domains. **Why it matters:** Names a specific supervision bug — correctness filtering without causal utility — that likely affects most tool-use SFT corpora.

- **SodaMem: Evidence-Grounded Temporal Graph Memory for LLM Agents** — Fengrong Wan, Chengcan Wu, Ningtao Lyu (arXiv cs.AI) · https://arxiv.org/abs/2608.08055
  Assistants running for weeks must remember what is *currently* true, not just what was said; flat RAG diaries optimize needle retrieval and under-serve currency, provenance, and temporal ordering. SodaMem extracts typed FactEvents with mandatory provenance spans, persists mention/occurrence/validity time with SUPERSEDES / CONTRADICTS / UPDATES edges under hybrid lexical-dense indexing, and answers through a planner–reader loop that gathers citable evidence first. On LongMemEval-S it reaches 92.8% at ~$0.0016/question with deepseek-v4-flash. Note: accuracy is self-graded with the same model as reader and judge, and cross-system costs are compiled estimates. **Why it matters:** Contradiction and supersession edges are what flat memory stores lack, and this quantifies the cost side too — with caveats the authors state plainly.
