## 📄 Research Papers — Top Picks
- **Skill Self-Play: Pushing the Frontier of LLM Capability with Co-Evolving Skills** — Siyuan Huang, Pengyu Cheng et al. · https://arxiv.org/abs/2607.22529
  Self-evolving LLM training is stuck between task diversity and verification reliability: environment-bound methods give precise feedback but narrow domains, while open-ended self-generation broadens tasks but lets bad rewards pollute training. The authors argue agent skills are the middle ground — each skill gives deep verifiable execution in one scenario, while dynamic routing across skills keeps the task space open. Skill-SP is a co-evolutionary framework with a proposer, a solver, and a dynamic skill controller. **Why it matters:** Frames "skills" as the unit that makes self-play verifiable, a directly reusable idea for agent-skill libraries.

- **AgentKVShift: Efficient KV Cache Reuse for Agentic Memory Systems** — Nilesh Prasad Pandey, Jason Kong et al. · https://arxiv.org/abs/2607.21604
  Memory-augmented agents re-encode structured memory units (summaries, keywords, tags) on every retrieval, and that prefill dominates inference cost. Existing training-free KV-reuse tricks were designed for raw RAG passages and degrade on structured agentic memory. AgentKVShift is a training-free, probe-guided KV residual correction applied per memory unit, exploiting the finding that the reuse residual decomposes into a shared memory-level offset plus small token terms. **Why it matters:** Directly cuts latency/cost for long-running agents with persistent memory.

- **DataFlow-Harness: A Grounded Code-Agent Platform for Constructing Editable LLM Data Pipelines** — Runming He, Zhen Hao Wong et al. · https://arxiv.org/abs/2607.16617
  Coding agents usually emit throwaway scripts instead of persistent, editable platform artifacts — the "NL2Pipeline gap". DataFlow-Harness makes an LLM agent build platform-native DAGs through typed incremental mutations, backed by DataFlow-Skills for procedural guidance, an MCP layer exposing the live operator registry and pipeline state, and a WebUI syncing chat with a visual DAG editor. Evaluated on a 12-task data-engineering benchmark. **Why it matters:** A concrete MCP-based pattern for making agent output editable state rather than one-shot code.

- **FlowEvo: Self-Evolving Agents through the Co-Evolution of Workflows and Executable Skills** — Zeyu Ren, Ling Yue et al. · https://arxiv.org/abs/2607.21596
  Useful procedures discovered while an agent solves a task are usually transient and never reused. FlowEvo is a training-free framework that compiles successful traces into reusable skill records, each pairing a callable artifact with structured guidance, admitted only after interface, replay, and safety checks. Records persist in an inference-time skill bank via workflow-to-skill compilation plus two coupled mechanisms for retrieval and refinement. **Why it matters:** Practical recipe for turning agent runs into a growing, vetted skill library without retraining.

- **Decoupled Attention Fusion: Accelerating RAG with Efficient KV Cache Reuse** — Xiabao Wu, Wentao Liu et al. · https://arxiv.org/abs/2607.21599
  Reusing precomputed document KV caches kills RAG's TTFT latency but breaks inter-document attention, and CacheBlend's selective attention degrades badly at long context. DAF splits attention into three stages — important-token self-attention to restore missing cross-document attention, question-document self-attention, and fusion — keeping accuracy while cutting recomputation. **Why it matters:** Long-context RAG serving gets cheaper without the usual accuracy cliff.

- **ToolGuardian: Declarative Security for AI Agent-Tool Interactions** — Arun Ravindran, Saurabh Deochake · https://arxiv.org/abs/2607.21835
  Third-party agent tools can look benign at the interface while hiding unsafe implementation, and current defenses lean on weak metadata or opaque LLM judgment. ToolGuardian does pre-admission vetting plus task-aware runtime authorization, using progressive characterization to turn evidence into structured facts: declared intent from descriptions, coarse behavior from syscall traces, observed effects from mock execution, and source analysis. Policy decisions stay deterministic and auditable across multi-tool composition. **Why it matters:** A supply-chain security model for MCP-style tool ecosystems that doesn't rely on an LLM to judge safety.

- **Towards Trustworthy and Cost-Efficient Data Integration: From Naïve RAG to Agentic RAG** — Chuangtao Ma, Arijit Khan · https://arxiv.org/abs/2607.22319
  Position paper on using knowledge-grounded LLMs and agents for enterprise data integration, where zero/few-shot LLMs still hit accuracy and cost walls from a persistent knowledge gap. It traces the evolution from classic RAG to GraphRAG and KG-RAG, showing how each bridges parametric and contextual knowledge, and defines trustworthiness as evidence-grounded, verifiable, hallucination-resistant reasoning. **Why it matters:** Useful map of where agentic RAG sits versus graph-grounded retrieval for enterprise workloads.

- **Nanbeige4.2-3B: Unlocking Agentic Capabilities in a Compact Model** — Nanbeige Lab · https://arxiv.org/abs/2607.22083
  A 3B non-embedding-parameter general agentic model pretrained from scratch on 28T tokens using a Looped Transformer that reuses the layer stack to add capacity without parameters. Training expands executable environments, task assets, and agentic scaffolds for SFT trajectories, then applies mixed-mode RLHF over Think/Non-Think responses, length-controlled reasoning RL, and agentic RL. Claims strong code-agent, office-agent, and complex tool-use performance while holding math/coding/science reasoning. **Why it matters:** Evidence that serious tool-use agents can run at 3B scale, which changes local/edge agent economics.

- **Solar Open 2 Technical Report** — Sungrae Park, Sanghoon Kim et al. · https://arxiv.org/abs/2607.20062
  A 250B-A15B MoE model built for long-horizon agentic tasks, reaching a 1M-token window via a hybrid stack interleaving one softmax layer per three linear-attention layers, no positional encoding, and a gated delta rule extended to negative eigenvalues. To fit a fixed compute budget it initializes from Solar Open 1 — transferring the 5.69B shared skeleton that survives the architecture change — and curates data for value per token. **Why it matters:** Whole-trajectory-in-context is becoming a design target, not just a benchmark number.

- **Trajectory-Aware Retrieval Agents for Temporal Decision-Making** — Jing Wang, Jie Shen, Xing Niu · https://arxiv.org/abs/2607.21625
  Standard RAG shreds chronological documents into isolated snippets and loses the temporal structure decisions depend on. TLM is a closed-loop agentic framework that iteratively refines its evidence set using SHAP-guided feedback, with a latent growth curve model over retrieved chunk embeddings to detect trends, turning points, and information gaps. Under a scorer-calibration assumption the refinement is monotonically non-decreasing. **Why it matters:** Retrieval for time-series-like text needs trajectory awareness, not just top-k similarity.

- **The Regression Tax: Decomposing Why Skills Help and Hurt LLM Agents** — Darshan Tank, Baran Nama · https://arxiv.org/abs/2607.22520
  Adding procedural skills to an agent is normally scored by average task-success gain, hiding the fact that skills also break tasks that previously worked. Across ~6,000 runs on two office-automation benchmarks and three harness stacks, the authors separate regressions (solved without skills, failed with) from residual failures, and find the best skills win mainly by regressing less rather than gaining more. Three causes identified, including "skill description osmosis" — a skill shifting behavior merely by sitting in context. **Why it matters:** Skill libraries need regression testing; average uplift is a misleading metric.

- **Zero-Shot Mission-Level Evaluation for Aerial MLLM Agents** — Suman Navaratnarajah, Taehyoung Kim et al. · https://arxiv.org/abs/2607.22014
  MissionBench evaluates MLLMs as embodied reasoning modules on 120 long-horizon aerial missions across five simulated 3D environments and four task families, from a single high-level instruction with only egocentric observations and action history. Across 22 open and closed models, the best solves under 35% of missions versus 84.4% for humans. **Why it matters:** Quantifies how far general MLLMs still are from reliable long-horizon embodied autonomy.

- **Deconstructing Off-Policy Ratios: Entropy-Scaled Trust Regions for Asynchronous Reinforcement Learning** — Guanqun Zhao, Zijun Xie et al. · https://arxiv.org/abs/2607.22186
  Asynchronous RL speeds LLM post-training by overlapping rollouts with optimization, but stale off-policy data can collapse the policy. The paper shows the natural scale of the importance ratio varies systematically with token entropy: at low entropy the train-inference discrepancy is amplified into sampling noise, at high entropy in-flight weight updates cause legitimate exploration — so a single uniform clipping threshold is wrong. **Why it matters:** Concrete fix for instability in the async RL setups now standard for agentic post-training.

- **Exploring Robust Multi-Agent Workflows for Environmental Data Management** — Boyuan Guan, Jason Liu et al. · https://arxiv.org/abs/2604.01647
  Swapping deterministic pipeline components for LLM agents changes the failure mode: plausible-but-wrong outputs pass shallow checks and propagate into irreversible actions like DOI minting and public release. EnviSmart, deployed on campus-wide storage, treats reliability as architecture via a three-track knowledge design separating governance constraints (behaviors), retrievable domain knowledge, and tool-using skills. **Why it matters:** Production-grounded pattern for agents that take irreversible actions.

- **Teaching LLMs to Self-Evolve: Cultivating Core Meta-Skills with Reinforcement Learning** — Shujin Wu, Cheng Qian, Xiusi Chen, Heng Ji · https://arxiv.org/abs/2607.21971
  Hypothesis: AlphaEvolve-style test-time evolution works because of meta-skills like self-reflection on environment feedback, which post-training normally ignores. MetaEvolve builds them via a data-synthesis pipeline, evolution-aware RL, and inference-time evolutionary search, grounded in coding where program execution gives continuous rather than binary reward. Training data is synthesized as evolution trajectories over successive program revisions. **Why it matters:** Targets the refinement loop itself rather than single-shot answer quality.
