## 📄 Research Papers — Top Picks
- **SKILL.state: Scalable Long-Horizon Agent Skills** — Badhe, Tiwari, Chung · https://arxiv.org/abs/2608.26263
  Existing agent runtimes keep long-running skills alive by appending every observation, action, and reasoning trace to an ever-growing conversation history, which degrades latency and eventually poisons the context. SKILL.state replaces that append-only history with an explicit, mutable execution state: at each step the model sees only the immutable skill specification, the current structured state, and the latest observation. Execution length is thus decoupled from context length. **Why it matters:** The most direct attack on the failure mode that kills long-horizon agents in production — context growth, not model quality.

- **WikiSkill: Compiling Agent Experience into Persistent Knowledge for Skill Evolution** — Tang, Rashtchian, Ferng, et al. · https://huggingface.co/papers/2608.27454
  Agent skills package reusable workflows, and recent work discovers them automatically from experience — but the insights driving skill development stay scattered across optimization histories and are never systematically reused. WikiSkill co-evolves skills with a persistent knowledge base, explicitly separating raw execution experience, accumulated knowledge, and executable skills, then continuously consolidating experience into the wiki that guides the next iteration. **Why it matters:** Separates "what the agent learned" from "what the agent can run," the structure skill libraries have been missing.

- **PILOT in the Loop: Live Self-Improvement for Long-Horizon Agents** — Xiao, Sun, Wu, et al. · https://huggingface.co/papers/2608.26530
  Most self-improvement methods only process a run's experience after it ends, so they can neither redirect the active run nor immediately validate the lesson they extracted. PILOT argues improvement should be live — using emerging experience both to steer the current run and to update the persistent harness — and notes existing architectures cannot do this: single-agent self-correction mixes execution and assessment in one context, while subagent delegation separates them but cannot redirect a running subagent. **Why it matters:** Turns post-hoc reflection into in-flight correction, the difference between salvaging a bad run and only logging it.

- **SPT: Skills as Pre-Training Data for Agentic Language Models** — Sun, Li, Cheng · https://arxiv.org/abs/2608.26563
  Agentic models are normally post-trained on tool-call traces and agent trajectories, which require task environments, execution, and verification — making broad tool coverage expensive. SPT instead applies causal language modeling to SkillCorpus, a collection of public multi-file skill packages that already encode reusable tool semantics and workflows but are typically only injected as inference-time context. **Why it matters:** Reframes the public skill ecosystem as free mid-training data instead of prompt-time payload.

- **BekchiAI: Measuring, Observing, and Controlling LLM Agents in One Click** — Toruk · https://arxiv.org/abs/2608.26867
  Agentic skills — sequencing tools correctly, planning under dependencies, judging untrusted inputs, grounding generated arguments — are poorly captured by accuracy-only leaderboards. BekchiAI pairs a benchmark of 13 tool-using ReAct agents across 7 categories (arithmetic, structured/SQL, security detection, URL grounding, planning, orchestration, tool-policy) totalling 2,057 deterministic tasks with a platform for observing and controlling live agents. **Why it matters:** Measurement and runtime observability in one artifact, which is how agent ops teams actually need them.

- **ProvenanceGuard: Source-Aware Factuality Verification for MCP-Based LLM Agents** — Alvarez, Rajan, Genuardi, et al. · https://arxiv.org/abs/2606.18037
  Standard factuality metrics ask whether an answer is supported by pooled evidence, missing a provenance-sensitive failure the authors call cross-source conflation: a claim is true somewhere but attributed to the wrong source. ProvenanceGuard consumes captured MCP traces with stable tool and source IDs plus raw outputs, decomposes answers into atomic claims, and verifies each against the source it was actually attributed to. **Why it matters:** In clinical, legal, and formulary settings, a wrong citation on a correct claim is still a compliance failure.

- **Do Multimodal Agents Really Benefit from Tool Use? A Systematic Study of Capability Gains** — Guo, Yu, Chen, et al. · https://arxiv.org/abs/2606.02357
  A tool-call trace does not prove the tool supplied answer-critical information. The authors compare two "thinking with images" agents (Thyme, DeepEyesV2) against Tool-Free counterparts and a Pure-Text Reasoner trained from the same source pool without tool-calling trajectories, across real-world understanding, OCR, chart understanding, and math. Tool access yields little consistent aggregate improvement. **Why it matters:** A rigorous negative result: much of the reported tool-use gain may be training-data effects rather than tools.

- **Don't Overthink, Don't Underthink: Toward Adaptive Reasoning in Agentic AI** — Mia, Amini · https://arxiv.org/abs/2608.26442
  Inference-time reasoning controls are usually fixed — preallocated token budgets, pre-execution difficulty estimates, activation-space interventions — and evaluated on standalone reasoning benchmarks rather than full agentic workflows. In real agentic systems reasoning demand shifts dynamically across planning, tool use, memory retrieval, and agent-to-agent interaction, so a fixed budget is excessive on easy steps and insufficient on hard ones. **Why it matters:** Reasoning budget is a per-step decision in agents, and treating it as a per-task constant burns tokens on both ends.

- **DIANOIA: Diagnostic Decomposition and Joint Optimization for Multi-Agent Reasoning** — Yang, Li, Zeng, et al. · https://arxiv.org/abs/2602.08586
  Multi-agent LLM systems beat single-agent baselines, yet practitioners cannot predict which design works on a new task or diagnose why one fails. DIANOIA decomposes multi-agent reasoning gain into three empirically measurable channels — coverage, fidelity, synthesis — and derives a diagnostic protocol that identifies which channel bottlenecks a given task. **Why it matters:** Replaces "try more agents and see" with a measurable account of where the gain actually comes from.

- **Zero-Shot Self-Orchestration with Ledger-Based Control for Improved LLM Coding Performance** — Gao, Khosrowshahi, Sun, et al. · https://arxiv.org/abs/2608.26480
  Multi-agent gains are usually confounded: pipelines change token budgets, tool calls, and prompts at once, so an aggregate win says nothing about what helped. This study isolates a single variable — a manager-worker scaffold over a shared filesystem workspace, no training and no per-benchmark tuning — against the same model answering in one pass, across nine models from 9B to ~2.8T parameters (five open-weight, four frontier closed) on the 100 latest hard LiveCodeBench problems. **Why it matters:** A controlled ablation of orchestration itself, which the multi-agent literature has largely skipped.

- **Benchmarking AI Agents for Hardware Design Automation via MCP Tool Calling** — Liparulo, Pierri · https://arxiv.org/abs/2608.26199
  Confidentiality around component specs and naming conventions often rules out hosted proprietary APIs for hardware design work, motivating locally deployed models. The authors build an MCP server reproducing the state and dependency logic of a real design tool, then test whether local LLM agents can execute repetitive, dependency-ordered operations — creating components, adding ports, wiring connections — reliably. **Why it matters:** Tests the local-model + MCP combination in exactly the confidentiality-constrained setting that pushes teams off frontier APIs.

- **RedEvoAgent: Automatic Red-Teaming Agent with Experience-Driven Skill Evolution** — Zhang, Liu, Chen, et al. · https://arxiv.org/abs/2608.27439
  Jailbreaks inside product-level execution harnesses trigger harmful tool use and persistent state changes, a strictly larger risk surface than unsafe text generation. Existing automatic red-teamers use fixed attacks, while trajectory-retrieval agentic attackers reuse misleading experiences due to retrieval bias and unclear tool credit, with full trajectories inflating context and hurting interpretability. RedEvoAgent is a black-box red-teamer that evolves reusable attack skills from experience instead. **Why it matters:** Agent red-teaming has to target the harness and its side effects, not just the model's text output.

- **MENTOR: Reinforcement Learning via Flexible Teacher-Optimized Rewards for Tool-Use Distillation** — Choi, Song, Kim, et al. · https://arxiv.org/abs/2510.18383
  Distilling tool use into small models via SFT generalizes poorly out-of-domain because it rigidly matches static teacher trajectories, while RL hits a capacity dilemma: sparse outcome rewards under-guide small models and strict trajectory matching over-constrains them. MENTOR uses teacher-optimized rewards that are flexible rather than trajectory-exact, targeting the middle ground. **Why it matters:** Small tool-using models are the cost floor for agent deployments, and OOD brittleness is their main blocker.

- **Agentic AI for operating scientific instruments for nanoscale characterization** — Ayar, Penedo, Mehdikhani, et al. · https://arxiv.org/abs/2608.26198
  Running an atomic force microscope requires continuous expert judgment — defining intent, translating it to instrument commands, assessing incoming data, adjusting imaging parameters, post-processing — and existing automation only hard-codes fragments of that loop. This work drives the executable portion of the AFM workflow with a general-purpose tool-augmented LLM wired to instrument functions. **Why it matters:** Real closed-loop instrument control, where a wrong tool call damages hardware rather than producing a bad string.

- **DSA: Evidence-Aware LLM-Agent Orchestration for Multi-Market Stock Research** — Zhu, Shi · https://arxiv.org/abs/2608.26990
  LLMs can summarize financial data, but an operational research system must first assemble heterogeneous evidence, expose which data and model capabilities are unavailable, and control how generated opinions propagate into the final report. DSA splits the workflow into evidence acquisition, structured context construction, model-routed analysis, optional role and strategy-skill reasoning, and report generation with selected context plus diagnostics. **Why it matters:** Explicitly surfacing missing evidence is what separates a research tool from a confident hallucinator.
