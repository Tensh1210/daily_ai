## 📄 Research Papers — Top Picks
- **The Router Within: Eliciting Native Skill Routing from a Frozen LLM** — Chen, Wang, Chen, Li, Huang · https://arxiv.org/abs/2609.15982
  Deployed harnesses route skills by preloading every skill's metadata into context, which disperses attention and caps library size; retrieval pipelines move selection out of context but also out of the agent's own judgment. Gavel shows the frozen agent LLM already carries the routing signal: two trained linear maps project mid-layer states of the task and each skill (per-skill banks built once at install) for a "glance", then a "verdict" resumes shortlisted skills' forward passes and reads the model's own likelihood and yes/no judgment, fused as a product of experts. Trained once, it transfers zero-shot to three public benchmarks and the new SkillTraj (372 simulated trajectories); on Qwen3-32B it beats progressive disclosure and retrieve-and-rerank pipelines carrying 1.2B–16B extra parameters by up to 13.4 points, and up to 21.9 when the skill need arises mid-rollout. In a bash-agent harness the same 32B triggers the correct skill more often than far larger frontier models running in Codex. **Why it matters:** Skill routing without skill text in context — read from the model's own activations — removes the context-window ceiling on library size.

- **MCPAgentBench: A Real-world Task Benchmark for Evaluating LLM Agent MCP Tool Use** — Liu, Liu, Dai, Yu, Yu, Yang, Han, Gao · https://arxiv.org/abs/2512.24565
  Existing MCP evaluation sets depend on live external MCP services and lack difficulty awareness. MCPAgentBench builds authentic tasks over real-world MCP definitions with simulated tools, run in a dynamic sandbox that presents candidate tool lists containing distractors so tool selection and discrimination are tested, not just invocation. Metrics cover both task completion and execution efficiency. Experiments on state-of-the-art LLMs reveal large performance gaps on complex multi-step tool invocations; code is open-source. **Why it matters:** A reproducible MCP benchmark with distractor tools is what you need to compare models on the tool-picking failure mode that actually bites in production.

- **When Malicious Instructions Persist: Persistent Memory Poisoning Attack on Harness-Based Agents** — Huang, Zhang, Jia · https://arxiv.org/abs/2609.13889
  Harnesses add persistent memory, tool use, and runtime control — and memory that persists across sessions is a new attack surface. PMPA embeds malicious instructions in benign external sources and induces the victim agent to write them into persistent memory without touching the framework; later sessions retrieve the poisoned memory and trigger further malicious actions and privacy leakage. On OpenClaw and Claude Code across backbones, modalities, and trigger scenarios, PMPA reaches average injection / cross-session attack success of 73.7%/55.5% and 66.9%/81.7% respectively while preserving benign task performance. A targeted prompt-level defense reduces injection in many settings but offers little protection once memory is already poisoned. **Why it matters:** Auto-memory in coding agents turns a one-time injection into a persistent backdoor; defenses have to guard the memory write path, not just the prompt.

- **Confuse the Model, Control the Flow: Understanding and Mitigating Privacy Leakage from LLM Agents with Information Flow Control** — Shim, Karim, Jakkula, Zhou, Liu, Wang, Li · https://arxiv.org/abs/2609.14003
  Personal agents must decide whether to disclose private data to a given party, and existing defenses put that judgment in the LLM over the same context an adversary controls — so enforcement and attack surface coincide. Three new attacks needing no prompt injection (Collaborative Workspace Lure, Semantic Obfuscation, Channel Decoupling) leak far more than the attacks those defenses were designed for. FLOWSEAL moves enforcement to a tool-level interceptor outside the LLM's context, grounded in data provenance and an information-flow-control lattice with controlled declassification. Across three benchmarks, five prompt baselines, and eight attacks — including a live agent calling tools via MCP — leak rates drop to near zero (e.g., 52.2% → 0.5%). **Why it matters:** Privacy for tool-using agents has to be enforced below the model, on data flows, not negotiated in the prompt.

- **Training Agents to Evolve with Their Harness: TaoLive Digital Avatar Agent Technical Report** — TaoLive AIGC LLM Team · https://arxiv.org/abs/2608.15763
  Evolvable harnesses — Skills, Hooks, prompts, tools updated independently of weights — enable fast iteration but expose a trade-off: large models adapt zero-shot yet miss latency targets, while compact models overfit to a fixed harness. Harness-Aware Training (HAT) applies Harness-State Augmentation (task-preserving transformations of skill identifiers/content, tool schemas, prompt structure, hook functions) through HSA-SFT, general on-policy distillation, and HSA-RL. HAT scores 94.8 on Live-Stream QA (base 80.3; best general LLM 93.0) and 94.6 on Harness-Variant QA (base 75.4), avoids the 7.7-point IFEval regression that fixed-harness SFT causes, and serves at 3.4 s P50 / 8.1 s P95 on one H20; it is deployed in Taobao Live with positive A/B results. **Why it matters:** If your skills and hooks change weekly, train the small model to be invariant to harness churn instead of retraining it per configuration.

- **When Agents Slow Down: Understanding LLM Agents' Test-Time Strategies via Elo-per-token Analysis** — Liu, Mang, Peng, Chai, Li, Pimpalgaonkar, Zettlemoyer, Dimakis, Cheung · https://arxiv.org/abs/2609.15309
  Agents allocate test-time compute adaptively (revise, use tools, explore, stop), which makes scaling hard to measure. Elo-per-token tracks the best solution at each token budget on open-ended tasks with continuous scores and aggregates orderings via Bradley-Terry into cross-task Elo. Across four agents on four benchmarks with sessions up to 100M tokens, agents initially convert tokens to Elo faster than independent sampling (whose Elo grows linearly in log compute) but marginal gains diminish and eventually fall below it, while top human contestants on shared AtCoder Heuristic tasks improve superlinearly. Using the "scaling inflection point" as per-session budget and splitting 100M tokens across parallel sessions gains +264 Elo over one long session and +355 over ten short ones. **Why it matters:** Long single sessions stop paying off at a measurable budget — restart in parallel at the inflection point instead of letting one agent grind.

- **The Stochastic Deputy: Structural Tenant Isolation for Tool-Using LLM Agents** — Baig, Gillani, Ali, Siddiqui · https://arxiv.org/abs/2609.14780
  Multi-tenant tools that accept a tenant identifier and validate it against the caller's entitlement delegate resource selection to a process whose context may hold attacker instructions — the "stochastic deputy" problem. The structural defense: remove tenant identity from the MCP tool schema, bind scope to a verified credential, and enforce below the agent. In a 373-trial ablation over eight model configurations and two transports, a correctly validated tenant parameter still served every out-of-scope attempt (26/26); with the parameter removed no tool signature could express the read, though 12/56 trials escaped by forging writable scope, showing the context must be cryptographically protected. On a multi-GB production dataset, set-valued scope caused a 57x latency hit under function-wrapped predicates; a JSON_TABLE lateral join recovered index access. **Why it matters:** Tenant isolation must live in the tool interface and credentials, because a model that can name a tenant will eventually name the wrong one.

- **SkillLift: Learning Dense Rubrics from Sparse Oracles for Efficient Skill Evolution** — Kang, Wen · https://arxiv.org/abs/2609.15396
  Skill self-evolution methods revise skill text from execution feedback, but every oracle evaluation costs a full agent rollout, confining search to failure-patching. SkillLift's insight is that ranking is a smoother target than score regression, so it learns an oracle-aligned rubric as a structured evaluation space via bilevel optimization: an inner loop revises skills against the frozen rubric at zero oracle cost, and an outer loop spends a few oracle rollouts to re-align the rubric by rank correlation. On complex agent benchmarks it beats existing auto-skill methods with 40–70% less token cost than frontier evolving methods; code is public. **Why it matters:** A learned rubric as a cheap surrogate makes evolving SKILL files affordable instead of one full rollout per edit.

- **MOSCOPT: Mixture-of-Skills Collective Optimization for LLM Agents** — Zhang, Yang · https://arxiv.org/abs/2609.14399
  Prompt and skill optimizers all tune a single text template, missing synergy between complementary strategies. MOSCOPT is a text-native, parameter-free algorithm that jointly optimizes a pool of N skills plus a gating skill that selects K skills per step, using "EditAdam" with internally maintained dual states and three-phase interleaved updates that improve monotonically without gradients. Across 5 benchmarks and 3 target LLMs it outperforms all baselines, and ablations confirm both selective activation and collective evolution are essential; code is released. **Why it matters:** Optimizing a skill library plus its router together, in text, is a practical path to better agents when you cannot touch weights.

- **LIMBO: Lifelong Inference-Time Memory and Budget Optimization for LLM Agents** — Sharma, Pandey, Gungor, Rosing · https://arxiv.org/abs/2609.14138
  Lifelong agents replay past interactions into the prompt, but every replayed trajectory competes with retrieval, reasoning, tool use, and verification for the same budget — and fixed replay policies ignore whether replay helps the current task. LIMBO frames this as inference-time memory allocation and learns online, in a single pass without modifying the agent, a per-task joint choice of memory strategy and inference budget. Across three backbones on LifelongAgentBench it achieves better cost-accuracy trade-offs than memory-augmented baselines, nearly matching the strongest at up to ~83% lower inference cost (~53% average), and adapts across models and environments without retraining. **Why it matters:** Memory should be a metered resource decided per task, not a fixed prompt tax.

- **ModularRSI: Modular and Generalizable Recursive Harness Self-Improvement** — Wu, Ren, Li, Li, Yang et al. · https://arxiv.org/abs/2609.14857
  Recursive self-improvement of agent harnesses tends to overfit to the evaluation benchmark, conflate systematic harness flaws with instance-specific reasoning, and entangle unrelated mechanisms in monolithic edits. ModularRSI contrasts successful and failed trajectories for the same task, aggregates evidence across tasks to find recurring deficiencies, and decomposes the harness into five modules — Agent Loop, Tool Use, Observation Management, Context Management, Task Completion Detection — each evolved within a restricted scope, then integrated. Evolution runs on 2,000 executable tasks curated to be disjoint from the downstream benchmarks, with results reported on Terminal-Bench 2.0 and SWE-Bench Verified. **Why it matters:** Benchmark-disjoint, module-scoped harness evolution is how you get improvements that transfer rather than memorized benchmark tricks.

- **Salesforce Koa: An Enterprise Language Model for Agentic Tool Use** — Chen, Niu, Liu, Zhao, Prabhakar et al. (Salesforce) · https://arxiv.org/abs/2609.15066
  Koa post-trains the open-weight Nemotron-3-Super-120B with GRPO on public and synthetic data (no customer data) to improve tool use and agentic capability while keeping general performance. The distinctive piece is a simulation-to-reward pipeline that expands workflow specifications — written in Agent Script, Salesforce's declarative Agentforce language, for enterprise domains — into persona-conditioned multi-turn tasks with task-resolution rewards grounded in successful tool use. Across public tool-use, agentic-reasoning, and CRM benchmarks Koa improves over its base, most clearly on multi-turn tool use, surpassing a strong proprietary baseline while trailing the strongest frontier models. **Why it matters:** Declarative workflow specs can be compiled into RL training signal, giving enterprises a repeatable way to specialize open models for their own agents.

- **EvoOntology: A Self-Evolving Ontology Layer for Data Agents** — Chong, Zhang, Fan, Du · https://arxiv.org/abs/2609.15779
  Data agents face an agent-data gap: heterogeneous tables, files, and databases live outside the agent, reachable only via generic tools, and neither raw exploration nor hand-built semantic layers scale. EvoOntology packages the ontology as an MCP server with schema, content, and tool layers that agents query at runtime, builds it autonomously with a builder agent, and refines it through attribution-guided typed edits accepted only after a backbone-conditional paired evaluation. On three data-agent benchmarks with four backbones it consistently beats strong baselines and existing semantic-layer approaches; code is public. **Why it matters:** Serving a self-maintaining semantic layer over MCP is a concrete pattern for giving agents structured knowledge of messy enterprise data.

- **Question's Gambit: The First Move Matters in Agentic Deep Search** — Hamidi Rad, Bigdeli, Arabzadeh, Ebrahimi, Clarke, Fung, Bagheri · https://arxiv.org/abs/2609.14412
  Deep research agents loop over search, read, and reason, yet even with strong lexical retrieval they fail to connect evidence-bearing documents to gold documents. Question's Gambit treats the first retrieval move as a design decision: it decomposes the question into clues, reformulates them into complementary searches, consolidates and reranks the pool, and hands the agent an opening context built for clue aggregation and answer verification. On BrowseComp-Plus it raises answer accuracy from 83.1% to 90.5% with gpt-5.5 over Pi-Serini, the strongest agentic baseline, and transfers to MultiHop-RAG; implementation is public. **Why it matters:** A well-engineered opening retrieval pass buys more than extra loop iterations — cheap to add to any deep-research agent.

- **HazardAuditor: From Executable Threats to Safer Computer-Use Agents** — Feng, Lin, Wen, Guo, Ma, Wu, Deng, Ji · https://arxiv.org/abs/2609.15134
  Computer-use agent risks emerge from runtime behavior across browsers, terminals, file systems, and services, which static prompt/response guards miss and executable safety platforms only score rather than supervise. HazardAuditor runs heterogeneous agents (Claude Code, Codex, Hermes, OpenClaw) in controlled environments and normalizes their interactions into a canonical event representation for cross-framework guard training. Guard Policy Optimization fixes a mismatch in token-level objectives where long rationales dominate gradients, converting deterministic safety outcomes into sequence-level advantages. Across benchmarks and systems it improves guard accuracy by up to 16.5 points over the strongest prior guard; code and models to be released. **Why it matters:** A guard trained on normalized execution traces from real coding agents is a more honest safety layer than one trained on chat transcripts.
