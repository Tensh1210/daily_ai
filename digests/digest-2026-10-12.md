## 📄 Research Papers — Top Picks
- **APEX-Harm: Evaluating Agent Safety in Shared Professional Workspaces** — Ziyi Yang et al. · https://arxiv.org/abs/2610.13623
  APEX-Harm benchmarks prompt and script injection against long-horizon agents doing finance, consulting and legal work in large shared workspaces (115-328 files per task) with email, calendar, chat, docs, spreadsheets and code execution exposed via MCP servers. Across 12 frontier models and 180 tasks each, Opus 5 and Sonnet 5 have the lowest attack success (8% and 20%), but task-specific script replacement and attacker-supplied generic scripts still succeed 73-84% of the time on average. Gemini 3.8 Flash scores best on tasks (0.877) yet is still compromised 33% of the time. **Why it matters:** Correct deliverables are not evidence of safe behavior; MCP workspace agents need injection evals on scripts, not just text.
- **RATED: Reliability-Aware AI Agent Tool Retrieval via Execution Dynamics** — Weiliang Chen et al. · https://arxiv.org/abs/2610.13889
  RATED makes tool retrieval reliability-aware: a frozen, contrastively fine-tuned dual-encoder handles semantic matching and a lightweight contextual bandit re-ranks candidates from live execution feedback. On the new EcoAgent benchmark (5,172 real tools, 210K+ query-tool pairs) it gives a 52.2% relative MRR gain over the ToolLLM retriever and cuts faulty tool selection from 86.2% to 2.9% under a 30% API outage, with <1 ms overhead. **Why it matters:** Tool retrievers for large MCP/tool catalogs should route around failing tools, not just match semantics.
- **VEPA: Verified Evolving Formal Policy for Lifelong LLM Agent Guardrails** — Duy Nguyen et al. · https://arxiv.org/abs/2610.12813
  VEPA represents an agent guardrail as a formal policy of executable symbolic rules over typed agent events. During deployment an LLM proposes policy patches from feedback, a deterministic verifier accepts only structurally valid, conflict-free policies, and an evidence-aware authority layer activates a rule only once it has enough support. It beats baselines on ASSEBench-Safety/Security and ATBench. **Why it matters:** Combines deterministic, inspectable guardrails with the ability to adapt to newly observed risks.
- **Humanize MLE Agents: Multi-Agent Session Alternation Beyond Single-Agent Limits** — Changye Li et al. · https://arxiv.org/abs/2610.13494
  Finds that long single-session MLE agents suffer 'long-horizon deceleration' and that custom harness gains fade as models improve ('harness staleness'). HMA instead alternates two agents on a shared workspace, caps each session at k experiments and resets context between sessions, backed by a context-reset semi-Markov analysis. It hits a 78.2% any-medal rate on 75 MLE-bench Kaggle tasks, +8.0 points over the best open-source baseline at a quarter of the time budget. **Why it matters:** Session alternation with context resets is a simple, harness-free alternative to ever-growing context engineering.
- **Do More Agents Help? Evaluating Accuracy and Cost in LLM Multi-Agent Workflows** — Yuhang Fu et al. · https://arxiv.org/abs/2606.05670
  BenchAgent compares six multi-agent workflow configurations against a single-agent reference across ten reasoning, coding and tool-use benchmarks, all on GPT-4.1 with shared tools and scoring (3,302 instances per config per run). Only EvoAgent beats the single agent (79.70% vs 76.65%); the other five trail by 1.7-8.8 points, and e.g. ChatEval uses 4.34x the tokens while losing pooled accuracy. **Why it matters:** Hard evidence that adding agents often costs more and helps less than a well-built single agent.
- **Proactive Agentic Orchestration** — Xueyang Feng et al. · https://arxiv.org/abs/2610.13485
  POrchestra lets sub-agents proactively message the orchestrator at any logical point to request harness adjustments without losing local execution continuity. On-Policy Orchestration Distillation (OPOD) attributes those revision requests back to earlier orchestration decisions as process supervision. Across deep research, digital-assistant and SWE benchmarks it improves success by 9.1% relative to the strongest baseline, with a better cost-performance trade-off. **Why it matters:** Gives orchestrator/sub-agent systems a two-way channel and a denser training signal.
- **LongHarness: Advancing Agentic Reasoning over 100M-Token Corpora via Stateful Evidence Management** — Songtao Huang et al. · https://arxiv.org/abs/2610.13075
  LongHarness is a model-agnostic harness for reasoning over corpora far beyond the context window. Evidence-Conclusion Coevolution uses unresolved conclusions to steer exploration and new evidence to revise conclusions, while Evidence Lifecycle Management keeps evidence current and traceable. With GLM-5.3-Flash it lifts OfficeQA Pro exact match from 15.8% to 60.2% (V1) and 4.4% to 61.1% (V2), and beats Claude Code by 12 points. **Why it matters:** Explicit evidence state curbs unbounded exploration and drift in long-corpus agents.
- **PACT: Privileged Trace Co-Training for Multi-Turn Tool-Use Agents** — Zhenbang Du et al. · https://arxiv.org/abs/2606.16215
  PACT post-trains multi-turn tool-use agents with expert traces used only as training-time signals: rollouts stay prompt-only, while a trace-conditioned RL surrogate and a component-aware SFT loss over reasoning and tool-call parts provide guidance, plus prompt-only anchoring. It beats strong SFT and RL baselines on FTRL, BFCL and ToolHop. **Why it matters:** A cleaner way to mix dense expert supervision with RL for tool-calling agents.
- **SWE-Critix: Post-Training Generalist Verifiers for Assessing Coding-Agent Trajectories** — Jiajun Hu et al. · https://arxiv.org/abs/2610.13356
  SWE-Critix is an SFT+RL pipeline for training generalist verifiers that read long coding-agent trajectories, predict whether the task was completed and explain why. Trained on CodeForge-Preview trajectories, a 30B verifier improves classification accuracy from 57% (base Qwen3-30B-A3B) to 66% after SFT and 78% after RL; models, data and code are released. **Why it matters:** Trained trajectory verifiers fill the gap when coding tasks lack an oracle test.
- **Competence-Aware Orchestration for LLM-Based Multi-Agent Systems** — Songmiao Wang et al. · https://arxiv.org/abs/2610.13144
  A two-stage orchestration framework first estimates the backbone LLM's competence on the current query, then adapts which roles are active and the communication graph. Across six benchmarks it averages 93.81%; for stronger backbones it raises accuracy from 87.22 to 89.97 while cutting tokens by 36%. **Why it matters:** Scale collaboration to difficulty instead of always paying for full multi-agent debate.
- **Imagine Before Acting: Prospective Skill Identification for LLM Agents** — Shuo Liu et al. · https://arxiv.org/abs/2609.01642
  Identifies Task-Skill Misalignment: task descriptions state objectives while skill documents describe capabilities and procedures, so useful skills get missed in retrieval or invocation. SkillDreamer imagines required capabilities as pseudo-skills to guide retrieval, and re-evaluates needed capabilities as subtasks emerge. It improves results on three agent-skill benchmarks across retrievers and LLMs. **Why it matters:** Directly relevant to skill-library agents where retrieval misses the right skill.
- **Work2Skill: Capturing Human GUI Experience for Reusable Agent Skill Induction** — Yuqi Huang et al. · https://arxiv.org/abs/2610.12984
  Work2Skill captures human desktop GUI demonstrations (screen, mouse/keyboard events, accessibility tree) via WorkRecorder, releases the WorkDemo-350 dataset, and induces reusable skills with workflow rules, step dependencies and completion checks. Induced skills raise scores by 4.7-10.5 points on MyPCBench and 3.1-7.5 on an OSWorld-Verified subset across four execution models. **Why it matters:** Turns human know-how into reusable computer-use agent skills.
- **Rollout-Time Intervention: Unlocking Agentic Reinforcement Learning Beyond Policy Limits** — Chen Xi et al. · https://arxiv.org/abs/2610.13438
  Rollout-Time Intervention uses reward-side evidence (evaluation rubrics) during rollout to turn failing agent trajectories into successful ones, giving learning signal on tasks the policy rarely solves. Off-policy intervention trajectories help once those with excessive distribution shift are filtered. It outperforms RL baselines on five benchmarks; code from Alibaba-NLP. **Why it matters:** Addresses training collapse when agent tasks exceed the policy's capability boundary.
- **Scaling Agentic Data for Long-Horizon Terminal Intelligence** — Shun Zou et al. · https://arxiv.org/abs/2610.13166
  TerminalHorizon is an automated synthesis engine for long-horizon terminal-agent data: it starts from real professional work, uses independent execution to detect work that environment construction quietly pre-solved, and progressively extends tasks under the same goal. 1.5K environments are used to SFT Qwen3.5-27B into TerminalHorizon-27B, which gains on all 12 coding-agent, production-agent and reasoning benchmarks. **Why it matters:** Data quality for long-horizon terminal agents hinges on not leaking the hard work into the environment.
- **A Baseline Assessment for the Agentic Web Technology Stack** — Vagner Figueredo de Santana et al. · https://arxiv.org/abs/2610.13703
  MASTIF is a test framework for Agentic Web stacks; the paper runs a baseline over 3 LLMs, 3 protocols and 4 agent frameworks on 300 Mind2Web tasks. Task-specific stack choices improve completion rate and efficiency and reduce verbosity and time. **Why it matters:** First apples-to-apples look at how protocol/framework choices interact in agent stacks.
