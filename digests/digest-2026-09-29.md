## 📄 Research Papers — Top Picks
- **MCP Error Messages Written for Developers Hurt the Most Capable Agents Most** — Xu, Wu · https://arxiv.org/abs/2609.35381
  Across 150 popular MCP servers, 949 of 3,001 error messages give a next step, and most credential-error steps ask for a terminal command, config change, or web page that a tool-only agent cannot perform. Testing five OpenAI models on BFCL tasks, agents followed these steps literally: on expired credentials the loss grew from 18 points for GPT-5.5 to 69 for GPT-6 Astra, and GitHub's bare "Wait before retrying." left only 6% recovered. Naming a server tool in the error (a login tool, or the call to repeat) raised recovery to 84–88%, and a one-sentence prompt to drop the step reached 82%. **Why it matters:** Cheap, actionable fix for MCP server authors: write error messages that point to tools the agent can actually call.
- **HTN Planning as a Coordination Layer for Multi-Server MCP Tool Orchestration** — Jacopin, Jacopin, Takahashi · https://arxiv.org/abs/2609.33731
  MCP isolates servers, so cross-server workflows are left to the LLM host, which makes them non-deterministic and costs one inference round-trip per tool call. Here an HTN planner produces a verifiable cross-server plan once, and a middleware executes it deterministically, binding data between servers with `${context.X}` templates and JSON-path extractors. It runs end-to-end against eight live third-party MCP servers over real biological databases across five domains. **Why it matters:** A reproducible, low-inference alternative to LLM-driven multi-server MCP orchestration.
- **Agents' Overreliance on Unreliable Tools** — Yang et al. · https://arxiv.org/abs/2609.05587
  The authors corrupt the returns of web search, an LLM sub-agent, and a code executor across 14 models. Agents adopt corrupted returns more than a third of the time for every tool, up to 68% for web search, often overriding answers they got right without tools and rarely warning the user even when their reasoning flags the conflict. Verification prompts reduce adoption while largely preserving accuracy on correct returns. **Why it matters:** Tool benchmarks assume tool outputs are correct; real agents need explicit verification of what tools return.
- **Report: Progressive Disclosure of Agent Skills** — Zhang et al. (Workday) · https://arxiv.org/abs/2609.35692
  In Workday's deployed LLM agents, skill libraries grow as users request features, raising operating cost. This report measures lazy-loading skills on demand (progressive disclosure) and finds it improves skill-retrieval quality while marginally increasing overall latency. **Why it matters:** Production evidence that lazy-loading skills is worth it: better retrieval for a small latency cost.
- **Omni-IO Skills: Harnessing Your Agent Omni-Native** — Li et al. · https://arxiv.org/abs/2609.31847
  Omni-IO Skills is a plug-and-play agent harness that adds multimodal production to existing agents through 27 hierarchical skills, a standard execution interface, dependency-aware orchestration, and a persistent Asset Registry. Multi-asset workflows run as execution graphs that schedule independent steps concurrently and reuse outputs across turns. On UniM-90 it raises input-support rates of GPT-5.6 Sol and Claude Sonnet 5 from about 40% to 100%. **Why it matters:** Shows skills plus a harness can extend modality coverage without retraining the base model.
- **SEABench: Benchmarking Endogenous Misalignment In Self-Evolving Agents** — Das et al. · https://arxiv.org/abs/2609.35596
  Self-evolving agents edit their own instructions, memory protocols, tools, and skills, and locally useful edits can later cause unsafe behavior without any attacker. SEABench provides 48 longitudinal task sequences in a personal-assistant environment, with paired non-evolving agents for causal attribution. Self-evolution raises task completion but often introduces safety failures absent in the baseline. **Why it matters:** Self-improvement has a safety cost that needs to be measured, not assumed away.
- **A Systematic Survey of Agentic Skills: Architecture, Lifecycle, and Security** — Badhe et al. · https://arxiv.org/abs/2608.29596
  The survey frames agentic skills as externalized procedural knowledge and maps a nine-stage lifecycle: discovery, authoring formats, storage, retrieval and routing, composition, execution and repair, lifelong adaptation, evaluation, and security governance. It also covers skill marketplaces, public registries, emerging attack vectors, and runtime defenses. **Why it matters:** A useful reference map for the fast-growing skills ecosystem, including its security surface.
- **RSI-Router: Evolving Subtask-Level LLM Routing and Skills for Cost-Efficient Agents** — Li et al. · https://arxiv.org/abs/2609.34712
  RSI-Router assigns models per subtask within long-horizon agent tasks and evolves model-specific skills through recursive self-improvement: subtask mining, routing-strategy evolution, skill evolution from routed-vs-large-model failure diffs, and Pareto router selection. Routing between DeepSeek-V4.1-Flash and Qwen3.5-9B, it beats the DeepSeek-only baseline at about 48% of the inference cost across five agentic benchmarks. **Why it matters:** Large-small model collaboration inside a task can halve agent cost without losing quality.
- **Continuous Context Management** — Hoy et al. · https://arxiv.org/abs/2609.35540
  CCM compacts context every turn: the agent emits an updated memory with each action, and the next prompt holds only the task, memory, and newest observation. On TerminalBench-2 with Claude Sonnet 4.6, Opus 4.6, GLM-5, and Kimi K3 it sharply cuts input tokens but lowers success for most models. GRPO with privileged full-history distillation improves CCM for open-weight models on WebShop. **Why it matters:** Per-turn compaction is cheap but lossy out of the box; training can close the gap.
- **MemAgent: Learning to Manage Heterogeneous Memory Providers for LLM Agents** — Wei et al. · https://arxiv.org/abs/2609.32521
  Evaluating 13 memory methods, the authors find none generalizes across benchmarks. MemAgent treats memory as routing: it decides which provider to retrieve from, whether to inject short-term memory, and which providers store new experience, trained with synthesized phase-specific supervision. It reports gains on GAIA, WebWalkerQA, and xBench-DS. **Why it matters:** Suggests agent memory should be a routed portfolio, not a single representation.
- **R²Flow: Recursive Self-Improvement via Recursive Skill Evolution** — Zhang et al. · https://arxiv.org/abs/2609.33867
  R²Flow alternates flow-based policy learning, independent verification, and versioned skill-library updates on a shared orchestration graph. The graph merges histories that differ only in step order, a signed utility separates skill benefit from mere frequency of use, and verifier evidence gates each library edit. **Why it matters:** Addresses why naive self-improving skill loops reward popular skills instead of useful ones.
- **X-Tree: Tokenizing Reusable Experience for Efficient Agent Generalization** — Cheng et al. · https://arxiv.org/abs/2609.32993
  Borrowing from tokenizers, X-Tree scores action spans by reusability and merges canonicalized actions into a tree of skills composed from sub-skills, with no LLM calls. It plugs into offline RL, online RLVR with a skill bonus, and on-policy self-distillation. Across WebArena, ScienceWorld, and WebShop at three model scales it beats standard recipes at matched data and budget. **Why it matters:** Moves skills from in-context prompts into the weights via training structure.
- **Skill2Env: Capability-Oriented Environment Synthesis from Skills for General Agents** — Xu et al. · https://arxiv.org/abs/2609.33772
  Skill2Env starts from a skill and synthesizes executable tasks, workspaces, and rubric-based evaluators guided by reusable difficulty patterns and task blueprints. Iterative Task Hardening uses solver execution evidence to make tasks that were too easy harder. **Why it matters:** Turns existing skill libraries into scalable post-training environments for tool-using agents.
- **CodeSkill: Latent Skill Abstraction for Long-Horizon Code Agents** — Wu et al. · https://arxiv.org/abs/2609.33243
  CodeSkill distills successful and failed code-agent trajectories into multi-level textual abstractions, then maps them to continuous latent skills via temporal variational inference plus RL. Learned skills are injected into a frozen LLM as latent prefixes, with an adaptive boundary mechanism gating skill switches from execution feedback. **Why it matters:** Optimizing at the skill level instead of the token level targets sparse-reward credit assignment in code agents.
- **AgentCL: Toward Rigorous Evaluation of Continual Learning in Language Agents** — Shu et al. · https://arxiv.org/abs/2606.02461
  AgentCL builds task streams with known cross-task relations (dependent, conventional, and independent) so it is clear what an agent actually learns and reuses over time. It is used to evaluate non-parametric memory designs for continual learning. **Why it matters:** Controlled task streams make agent-memory claims testable instead of anecdotal.
