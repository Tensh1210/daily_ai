## 📄 Research Papers — Top Picks
- **SPyCE: Skill-Policy Co-evolution for Multimodal Agents** — arXiv cs.CL · https://arxiv.org/abs/2607.13854
  Multimodal agents that think with images iteratively manipulate visual evidence and call tools over many steps, but RL methods collapse trajectories to scalar rewards so the policy must rediscover reusable tool-use patterns on every task. Memory-based alternatives keep past experience but only retrieve at test time, never updating the policy. SPyCE distills reasoning trajectories into reusable skills and co-evolves that skill library with the policy so learned patterns are absorbed rather than re-retrieved. **Why it matters:** Directly targets the biggest inefficiency in agent RL — throwing away reusable tool-use structure every episode.

- **ReCache: Efficient KV Cache Reuse and Compression for Tool-Augmented LLM Agents** — arXiv cs.CL · https://arxiv.org/abs/2608.19662
  Agentic models re-encode the same tool and skill schemas in different combinations and orders, which defeats standard prefix caching. ReCache caches each resource representation independently using resource-wise attention that removes cross-resource interactions and assigns resource-local positions, producing composition-invariant KV blocks. It then restricts resource visibility to cut inference compute and memory. **Why it matters:** Tool and skill schema re-encoding is a real serving cost for agent stacks; composition-invariant KV blocks make caching survive reordering.

- **Break It Down, Pass It On: Cross-Task Skill Transfer in LLM Agents** — arXiv cs.CL · https://arxiv.org/abs/2608.20274
  Agents can induce skills from finished tasks and reuse them later, but induced skills often transfer unreliably and can actively hurt the agent that retrieves them. This controlled study varies two axes: task-level vs subtask-level skill induction, and text vs code skill format. It maps when induced skills genuinely transfer across tasks versus when they degrade performance. **Why it matters:** Practical guidance for anyone building a self-improving skill library — granularity and format decide whether reuse helps or harms.

- **Can Agent Memory Systems Track Evolving State?** — arXiv cs.CL · https://arxiv.org/abs/2608.19652
  Existing memory benchmarks are mostly recall-shaped, while real long-horizon agents must track a world whose facts, constraints, and decisions get revised. The authors define this as state tracking and release StateMemBench, 234 multi-session scenarios where answers must reflect the current state rather than a superseded one. **Why it matters:** Recall accuracy is the wrong metric for agent memory; superseded-fact errors are the failure mode that actually bites in production.

- **Right Family, Wrong Skill: Benchmarking Risk Exposure in Agent Skill Retrieval** — arXiv cs.IR · https://arxiv.org/abs/2606.10388
  Skill libraries are routable software assets: a retrieved skill injects instructions, scripts, resource bindings, and execution assumptions into the agent. The paper studies same-capability risk-exposure retrieval, where the system finds the right capability family but picks a risky sibling that differs on execution assumptions. Each benchmark unit pairs a helpful skill with a query-specific risky twin. **Why it matters:** Skill retrieval is a security surface, not just a relevance problem — close-enough retrieval can hand the agent a dangerous variant.

- **PolicyGuide: From Guarding One Action to Guiding the Whole Workflow for Policy-Compliant LLM Agents** — HF Papers · https://huggingface.co/papers/2608.19861
  Customer-service agents fail compliance in two ways: forbidden actions, and omitted procedural steps such as identity verification or confirmation. Runtime action-local guards catch the first but cannot steer a multi-step procedure, while workflow systems optimize completion rather than safety. PolicyGuide compiles each domain policy into a workflow that guides the agent through the whole procedure. **Why it matters:** Moves agent guardrails from per-call filters to process-level enforcement, which is where regulated deployments actually break.

- **AI4AI-Bench: Benchmarking LLM Agents in Algorithmic Design for Recursive Self-Improvement** — arXiv cs.CL · https://arxiv.org/abs/2608.20318
  Recursive self-improvement hinges on whether an agent can improve the training algorithm itself — the objective or update rule that changes the compute-to-capability exchange rate for every later run. Existing suites can be won by collecting more data or tuning hyperparameters, so they never isolate algorithmic design ability. AI4AI-Bench is built to isolate exactly that capability. **Why it matters:** Gives a measurable handle on an RSI claim that is usually argued rather than benchmarked.

- **EnvHarness: Awakening Static Worlds for Agent Learning** — HF Papers · https://huggingface.co/papers/2608.19880
  Agent training environments are hand-built and static — blind to the weaknesses of the agent and quickly outgrown. Existing environment-generation work needs domain-specific pipelines and expensive or unreliable verifiers, and still yields static worlds. EnvHarness is a programmable layer of plug-in components that wraps an existing environment and reshapes its behavior without modifying it. **Why it matters:** Cheap way to keep training environments adversarial as the agent improves, instead of rebuilding benchmarks from scratch.

- **MemTrapBench: Benchmarking Cognitive Traps in LLM Memory Use** — HF Papers · https://huggingface.co/papers/2608.20202
  Memory benchmarks mostly check whether information is extracted, stored, and retrieved correctly, ignoring how a retrieved memory reshapes reasoning on the current task. The authors identify memory-induced cognitive traps: faithfully recorded, semantically relevant memories that still distort beliefs and degrade performance. MemTrapBench systematically evaluates these failure modes. **Why it matters:** Correct retrieval is not sufficient — relevant memory can still poison the current decision, which no recall metric detects.

- **Reward-Guided Autoregressive Graph Generation for Efficient Multi-Agent Communication Topology Design** — arXiv cs.CL · https://arxiv.org/abs/2608.20099
  LLM multi-agent systems buy reasoning performance with heavy token consumption, and prior automatic topology design (ARG-Designer) frames the problem as autoregressive graph generation with no incentive for sparsity. RGA-Designer adds an RL-style reward that explicitly pushes toward sparse, efficient communication graphs. **Why it matters:** Multi-agent token cost is mostly topology cost; making sparsity a training objective attacks it at the source.

- **Hallucination as a Feature, not a Defect: Evaluating a multi-agent architecture to transform speculative language-model outputs into testable scientific hypotheses** — arXiv cs.CL · https://arxiv.org/abs/2608.19206
  Alignment that suppresses hallucination also suppresses combinatorial creativity, which the authors treat operationally as semantic overfitting and diversity collapse. They propose a Rust-based multi-agent orchestration contrasting narrative daydreaming against executive control, converting speculative outputs into testable scientific hypotheses. **Why it matters:** Reframes hallucination control as a routing problem between generative and verifying agents rather than a global suppression setting.

- **Multi-Agent Orchestration with the Common-Sense Reasoning Capabilities of LLMs for Autonomous Driving** — arXiv cs.CL · https://arxiv.org/abs/2608.20129
  RL and rule-based controllers are reliable but degrade where contextual reasoning is required, while putting an LLM directly in the control loop adds latency and hallucination risk. The paper orchestrates multiple agents so LLM common-sense reasoning informs decisions without taking direct vehicle control. **Why it matters:** A concrete pattern for using LLMs in safety-critical loops — advisory layer, not actuator.

- **FlashPrefill V2: Block-Sparse Prefill Attention for Long-Context LLM Serving** — HF Papers · https://huggingface.co/papers/2608.19758
  Quadratic attention makes the prefill phase the dominant cost in long-context serving. FlashPrefill V2 takes the earlier prototype — instantaneous pattern discovery with max-based dynamic thresholding — and hardens it for production along three dimensions, including block-sparse attention suited to real serving stacks. **Why it matters:** Long-context agents pay prefill cost on every turn; production-grade sparse prefill is a direct latency and cost win.

- **Inject, Align, Recover: Staged Post-Training for Retrieval-Free Document Knowledge Internalization** — HF Papers · https://huggingface.co/papers/2608.20281
  LLMs fail on questions about a bounded document collection when those documents are not retrieved at inference time. IAR is a three-stage post-training framework that separates structured document knowledge injection, QA behavior alignment, and general-ability recovery, unlike undifferentiated continued pretraining. **Why it matters:** An alternative to always-on RAG for fixed corpora, with an explicit step to avoid the usual capability regression.

- **Doc-V*: Coarse-to-Fine Interactive Visual Reasoning for Multi-Page Document VQA** — arXiv cs.CL · https://arxiv.org/abs/2604.13731
  Multi-page DocVQA forces a trade-off: end-to-end models scale badly with document length, while visual retrieval pipelines are brittle and passive. Doc-V* is an OCR-free agentic framework treating the task as sequential evidence aggregation — start from a thumbnail overview, then actively navigate via semantic retrieval into specific regions. **Why it matters:** Agentic navigation beats one-shot ingestion for long visual documents, and it stays OCR-free.
