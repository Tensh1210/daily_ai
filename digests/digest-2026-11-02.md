## 📄 Research Papers — Top Picks
- **EvoMCP: Co-evolving MCP agents and training data** — Xuanang Gao et al. · https://arxiv.org/abs/2610.41479
  Proposes an agent–data mutual evolution loop for fine-tuning MCP agents: rollout feedback identifies capability gaps, verified seed tasks are mutated into new executable tasks (keeping verifiers aligned), fresh trajectories are generated, and the student is re-fine-tuned. It replaces static SFT datasets with a curriculum that tracks what the agent still gets wrong. **Why it matters:** A concrete recipe for continually improving MCP tool-using agents without hand-curating new data each round.
- **Mage-VL-Cowork: A Full Training Recipe to Learn Hybrid Computer Use From Evolved Harnesses** — Xiaoyi Zhang et al. · https://arxiv.org/abs/2610.40747
  A 4B computer-use agent that mixes GUI interaction with code/terminal execution in one policy, trained via a five-stage midtraining→SFT→RL curriculum. Its Mage-CUA-Forge pipeline synthesizes ~294K desktop/web tasks across 6,915 skills at 82.6% lower per-task cost, and evolves the teacher harness rather than distilling a fixed teacher. **Why it matters:** Shows small open CUAs can get strong by investing in harness evolution and skill-conditioned task synthesis.
- **How Much Can Tool Calls Reveal About You? Privacy Leakage from Tool-Call Traces** — Donghang Duan et al. · https://arxiv.org/abs/2610.41885
  Introduces PrivacyTrace (1,000 synthetic profiles, 4,000 trajectories, real tools from 25 MCP servers) to test whether observers can infer user attributes from tool-call traces alone. LLM attackers reach 26.25% profile-inference success vs 17.97% from prior guessing, with tool arguments and returned results leaking the most. **Why it matters:** MCP servers and logs see user signal even without the conversation — a real privacy surface for agent deployments.
- **Completeness and Cost of Retrieval Structures for Multi-Tool Requests in LLM Agents** — Shuyang Zhang · https://arxiv.org/abs/2610.41905
  Compares six tool-retrieval structures (lexical/dense, LLM decomposition, LLM-navigated hierarchies, server-then-tool, dependency graphs, set-level retrievers) on AppWorld and MCP-Bench (257 MCP tools). It measures completeness@k — whether the entire required tool set is retrieved — alongside LLM calls, tokens and latency. **Why it matters:** Multi-tool agents fail if any single tool is missed; this gives a cost/completeness map for choosing a tool retriever.
- **Subquadratic Attention with a Hierarchical Tree-Structured Indexer** — Leon Lufkin et al. (Zyphra) · https://arxiv.org/abs/2610.42112
  Zyphra Hierarchical Attention (ZHA) builds a tree of recursively compressed key summaries over the KV cache; queries traverse it top-down to select a sparse key subset. Unlike sparse methods whose indexers are themselves quadratic, growing the tree depth makes total cost asymptotically subquadratic while keeping attention's expressiveness. **Why it matters:** A credible path to genuinely subquadratic long-context attention rather than constant-factor speedups.
- **SoK: Agentic Retrieval-Augmented Generation (RAG): Taxonomy, Architectures, Evaluation, and Research Directions** — Saroj Mishra et al. · https://arxiv.org/abs/2603.07379
  A systematization-of-knowledge paper that formalizes agentic RAG loops as finite-horizon POMDPs with explicit control policies and state transitions. It builds a taxonomy of architectures, reviews fragmented evaluation practices, and catalogs reliability risks and open directions. **Why it matters:** A shared vocabulary and framework for a fast-growing but inconsistent design space.
- **EvoMemBench: Benchmarking Agent Memory from a Self-Evolving Perspective** — Yuyao Wang et al. · https://arxiv.org/abs/2605.18421
  A unified agent-memory benchmark organized by scope (in-episode vs cross-episode) and content (knowledge vs execution). Comparing 15 memory methods against long-context baselines under one protocol, it finds current memory systems far from general and long-context baselines highly competitive. **Why it matters:** A sober check before adding complex memory layers to agents — plain long context is often as good.
- **AgentOrch: How Close Can Global Orchestration Come to Step-by-Step Interaction?** — Zijie Liu et al. · https://arxiv.org/abs/2610.33375
  Benchmarks plan-the-whole-workflow-upfront ("Global") orchestration against step-by-step agent loops on 650 enterprise SOPs and 3,220 runtime variants. Step-by-step stays more accurate for every model, but the gap has shrunk ~79% from early to current models while Global avoids repeated LLM calls. **Why it matters:** Quantifies when precompiled workflows are good enough to cut inference cost in enterprise agents.
- **Context as Infrastructure: Knowledge Compilation for Retrieval in Agentic Systems with Harnesses** — Zhichang Yu et al. · https://arxiv.org/abs/2610.41172
  A search harness with only BM25/grep and MiniMax M3 hits 85% on BrowseComp-Plus and 91% on FRAMES, so accuracy is largely solved — the real problem is context waste from repeated queries and rereads. The authors propose "knowledge compilation" (hierarchies, entity graphs, timelines, wikis) as an ingestion layer; it gave no detectable accuracy gain on FRAMES but targets context efficiency. **Why it matters:** Reframes agentic RAG engineering from better retrievers to disciplined context budgets.
- **TraceSpec: Understanding and Improving Speculative Decoding for LLM Agents** — Jihao Zhao et al. · https://arxiv.org/abs/2610.41177
  Analyzes speculative decoding on agent trajectories (browsing, SWE) with a 12.5K-state corpus, showing aggregate acceptance rates can hide drops at specific late-stage actions. TraceSpec trains draft models on intermediate assistant turns guided by trajectory conditions. **Why it matters:** Agent workloads differ from chat; draft models need agent-aware training to deliver real speedups.
- **Natural Language Actor-Critic: Scalable Off-Policy Learning in Language Space** — Joey Hong, …, Sergey Levine · https://arxiv.org/abs/2512.04601
  Targets unstable, sample-hungry policy-gradient training of long-horizon LLM agents with sparse rewards. NLAC uses an LLM critic that produces natural-language evaluations to guide off-policy policy improvement in language space instead of relying only on scalar trajectory rewards. **Why it matters:** A more sample-efficient alternative to pure policy-gradient training for tool-use and web agents.
- **Structure-Aware Skill Retrieval and Arbitration for Optimization Modeling** — Anran Liu et al. · https://arxiv.org/abs/2610.41909
  ArchOR is a skill agent for turning natural-language optimization problems into solver-checked answers, adding centroid-aware skill representations and signature-guided (weighted Jaccard) retrieval over cached skills. An arbitration rule decides when the structural route overrides the baseline selector. **Why it matters:** Evidence that structured skill libraries make agents robust to paraphrased tasks.
- **STRIATUM-CTF: A Protocol-Driven Agentic Framework for Autonomous CTF Solving** — James Hugglestone et al. · https://arxiv.org/abs/2603.22577
  Exposes offensive-security tools as strictly typed, schema-validated MCP functions; the protocol layer rejects out-of-schema calls before execution and returns structured errors. This addresses malformed commands, hallucinated options and lost state common in shell-piping agents. **Why it matters:** A clear case study of MCP schema validation as a reliability layer for long-horizon tool agents.
- **Ax-Prover: A Deep Reasoning Agentic Framework for Theorem Proving in Mathematics and Quantum Physics** — Benjamin Breen et al. · https://arxiv.org/abs/2510.12787
  A multi-agent Lean prover that couples LLM reasoning with Lean tools via MCP, running autonomously or with human experts. It is benchmarked against frontier LLMs and specialized provers on public math sets plus new abstract-algebra and quantum-theory Lean benchmarks. **Why it matters:** General LLMs plus MCP tooling can compete with specialized provers across scientific domains.
- **Search When Needed, Proceed When Reliable: Metacognitive Reliability Supervision for Efficient Agentic Search** — Minhao Sun et al. · https://arxiv.org/abs/2610.41738
  Argues outcome-based rewards are a noisy signal for deciding when to search, since results mix generation randomness, retrieval quality and reasoning. Proposes a metacognitive reward based on the reliability of intermediate reasoning states, rewarding searches that are needed and that actually change the answer. **Why it matters:** Fewer unnecessary tool calls in search agents without sacrificing accuracy.
